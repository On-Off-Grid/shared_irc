# 📚 الدرس 2: كيفاش TCP كايخدم — الرحلة الكاملة ديال الرسالة

---

# Goal

> تفهم كيفاش TCP كايدير داخلياً من اللحظة اللي جهاز واحد كايصيفط بيانات حتى اللحظة اللي الجهاز الآخر كايستقبلها — كيفاش البيانات كاتتقسم، كاتمشي عبر الشبكة، وكاتتجمع من جديد.

---

# Explanation

## 1. شنو هي الشبكة (Network) ؟

الـ **Network** هي مجموعة ديال الأجهزة (حواسيب، تيليفونات، Servers...) اللي متصلين مع بعضياتهم باش يتبادلو المعلومات.

أبسط شبكة فالعالم هي **جوج حواسيب متصلين بكابل**:

```
  ┌──────────┐                          ┌──────────┐
  │ حاسوب A  │ ════════════════════════ │ حاسوب B  │
  │  (أحمد)  │        كابل              │  (سارة)  │
  └──────────┘                          └──────────┘
```

ولكن الإنترنت ماشي جوج حواسيب — هو **ملايير** ديال الأجهزة متصلين مع بعضياتهم عبر **ملايين** ديال الكوابل والأجهزة الوسيطة:

```
  ┌──────────┐     ┌──────┐     ┌──────┐     ┌──────┐     ┌──────────┐
  │ حاسوب A  │─────│Router│─────│Router│─────│Router│─────│ حاسوب B  │
  │  (أحمد)  │     │  #1  │     │  #2  │     │  #3  │     │  (سارة)  │
  └──────────┘     └──────┘     └──────┘     └──────┘     └──────────┘
                       │            │
                   ┌──────┐    ┌──────┐
                   │Router│    │Router│
                   │  #4  │    │  #5  │
                   └──────┘    └──────┘
                       │            │
                   ┌──────┐    ┌──────┐
                   │ جهاز │    │ جهاز │
                   │ آخر  │    │ آخر  │
                   └──────┘    └──────┘
```

الـ **Router** هو جهاز وسيط كايعرف كيفاش يوجه البيانات من مكان لمكان. بحال **إشارة المرور** اللي كاتقول للسيارات: "سير من هنا" ولا "دور من هنا."

**ملاحظة مهمة:** ملي كاتصيفط رسالة عبر الإنترنت، الرسالة كاتمر على **بزاف** ديال الـ Routers قبل ما توصل. ما كاتمشيش مباشرة من عندك للطرف الآخر.

---

## 2. كيفاش جوج حواسيب كايتواصلو ؟

باش جهاز A يتواصل مع جهاز B عبر الشبكة، خاصهم **3 حاجات**:

```
┌────────────────────────────────────────────────────────┐
│               الشروط ديال التواصل                       │
│                                                        │
│   1. العنوان ديال المرسل        → IP Address ديال A    │
│   2. العنوان ديال المستقبل      → IP Address ديال B    │
│   3. القواعد ديال التواصل       → Protocol (TCP)       │
│                                                        │
│   + رقم الباب ديال الخدمة       → Port                 │
└────────────────────────────────────────────────────────┘
```

بلا هاد الحاجات، الأجهزة ما يقدروش يتفاهمو. بحال ملي كاتبغي تصيفط واحد الطرد: خاصك تعرف **فين** كاتصيفطو (العنوان)، و**كيفاش** كاتصيفطو (البوسطة؟ DHL؟ — القواعد).

---

## 3. شنو هو الـ IP Address ؟

الـ **IP Address** هو العنوان الفريد ديال كل جهاز فالشبكة.

بحال عنوان الدار ديالك: "زنقة X، رقم Y، المدينة Z". بيه كايعرفو الأجهزة الأخرى فين يصيفطو ليك البيانات.

```
┌─────────────────────────────────────────────────┐
│              أمثلة ديال IP Addresses              │
│                                                 │
│   حاسوب أحمد:    192.168.1.10                   │
│   حاسوب سارة:    85.214.47.23                   │
│   localhost:      127.0.0.1  ← "أنا راسي"       │
│                                                 │
│   كل رقم من 0 لـ 255                            │
│   4 أرقام مفصولين بنقط (IPv4)                   │
└─────────────────────────────────────────────────┘
```

### شنو هو `127.0.0.1` ؟

هاد العنوان خاص بزاف: كايعني **"أنا كانهضر مع راسي"**. ملي كاتقول للبرنامج ديالك "تصل بـ `127.0.0.1`"، كاتقول ليه "تصل بجهازك نفسو."

ف ft_irc، غادي تستعمل `127.0.0.1` بزاف: الـ Server والـ Client غادي يكونو فنفس الحاسوب ديالك ملي كاتجرب.

```
┌────────────────────── حاسوب ديالك ───────────────────────┐
│                                                          │
│  ┌─────────────────┐     127.0.0.1     ┌──────────────┐  │
│  │  IRC Client     │ ◄══════════════► │  IRC Server   │  │
│  │  (irssi)        │                   │  (ircserv)    │  │
│  └─────────────────┘                   └──────────────┘  │
│                                                          │
│       الاثنين فنفس الجهاز — كايتواصلو عبر localhost      │
└──────────────────────────────────────────────────────────┘
```

---

## 4. شنو هو الـ Port ؟

الـ **Port** هو رقم الباب فالجهاز.

جهاز واحد يقدر يشغل **بزاف ديال الخدمات** فنفس الوقت: موقع ويب، SSH، IRC Server... كيفاش كايعرف الجهاز شمن خدمة كاتبغي؟ عن طريق الـ **Port**.

```
تخايل عمارة فيها بزاف ديال الشقق:

      ┌────────────────── العمارة = الجهاز ──────────────────┐
      │  العنوان ديال العمارة: 192.168.1.5 (IP Address)      │
      │                                                      │
      │  ┌────────────┐  ┌────────────┐  ┌────────────┐     │
      │  │  شقة 22    │  │  شقة 80    │  │ شقة 6667   │     │
      │  │ ──────────  │  │ ──────────  │  │ ──────────  │     │
      │  │  SSH        │  │  الموقع    │  │ IRC Server │     │
      │  │  Server     │  │  HTTP      │  │ (ircserv)  │     │
      │  └────────────┘  └────────────┘  └────────────┘     │
      │                                                      │
      │  العنوان الكامل ديال IRC: 192.168.1.5:6667           │
      └──────────────────────────────────────────────────────┘
```

**ملاحظات مهمة:**

| النطاق | الشرح |
|---|---|
| `0` — `1023` | **Well-known Ports** — محجوزين (خاصك Root). مثلاً: 80 = HTTP, 443 = HTTPS |
| `1024` — `49151` | **Registered Ports** — تقدر تستعملهم. مثلاً: 6667 = IRC |
| `49152` — `65535` | **Dynamic Ports** — كايستعملهم النظام مؤقتاً |

ف ft_irc، نتا اللي كاتختار الـ Port:

```
./ircserv 6667 mypassword
          ^^^^
          الـ Port اللي الـ Server غادي يتسنى فيه
```

### علاش خاصنا IP + Port مع بعضياتهم ؟

```
  IP Address بوحدو  →  كاتعرف الجهاز ولكن ما كاتعرفش شمن خدمة
  Port بوحدو        →  كاتعرف الخدمة ولكن ما كاتعرفش شمن جهاز
  IP + Port          →  كاتعرف الجهاز + الخدمة = العنوان الكامل ✅

  192.168.1.5:6667  =  "الجهاز 192.168.1.5، الخدمة فالباب 6667"
```

## 5. علاش البيانات ما يمكنش تمشي ككتلة وحدة كبيرة ؟

هاد النقطة مهمة بزاف باش تفهم علاش TCP كايقسم البيانات.

تخايل أحمد بغا يصيفط هاد الرسالة لسارة:

```
"Hello Sarah, how are you today?"
```

هاد الرسالة صغيرة، ولكن تخايل بلاصتها شي ملف كبير — 100 ميغا مثلاً. واش يمكن يصيفطو ككتلة وحدة؟ **لا!** وهاد الأسباب:

```
┌────────────────────────────────────────────────────────────┐
│                 علاش ما يمكنش ككتلة وحدة ؟                 │
│                                                            │
│  ❌ السبب 1: الحجم                                         │
│     الشبكة عندها حد أقصى لحجم البيانات اللي تقدر           │
│     تمر فدقة وحدة (MTU ≈ 1500 Bytes غالباً)              │
│                                                            │
│  ❌ السبب 2: الاحتكار                                      │
│     إلا شي واحد صيفط كتلة كبيرة، غادي يحتاكر             │
│     الشبكة كاملة وما يخلي حتى واحد آخر يصيفط             │
│                                                            │
│  ❌ السبب 3: الخطأ                                         │
│     إلا توضرات كتلة كبيرة فالطريق، خاصك تعاود            │
│     تصيفط 100 ميغا كاملة! ولكن إلا توضر جزء صغير،        │
│     تعاود تصيفط غير داك الجزء                              │
│                                                            │
│  ❌ السبب 4: المرونة                                       │
│     القطع الصغار يقدرو يمشيو فطرقان مختلفين               │
│     ويوصلو بسرعة أكبر                                     │
└────────────────────────────────────────────────────────────┘
```

**الحل:** TCP كايقسم البيانات لقطع صغار اسمهم **Segments** (ولا **Packets** بشكل عام).

---

## 6. شنو هو الـ Packet (ولا TCP Segment) ؟

الـ **Packet** هو قطعة صغيرة من البيانات اللي كاتمشي عبر الشبكة بشكل مستقل.

كل Packet فيها **جوج أجزاء**:

```
┌──────────────────────────────────────┐
│              PACKET                  │
│                                      │
│  ┌──────────────────────────────┐   │
│  │          HEADER              │   │
│  │  ────────────────────────    │   │
│  │  المرسل:     192.168.1.10   │   │
│  │  المستقبل:   85.214.47.23   │   │
│  │  Port المرسل:    52431      │   │
│  │  Port المستقبل:  6667       │   │
│  │  Sequence Number: 1         │   │
│  │  الحجم:      15 Bytes       │   │
│  └──────────────────────────────┘   │
│                                      │
│  ┌──────────────────────────────┐   │
│  │          DATA (الحمولة)       │   │
│  │  ────────────────────────    │   │
│  │  "Hello Sarah, "            │   │
│  └──────────────────────────────┘   │
│                                      │
└──────────────────────────────────────┘
```

- **الـ Header** = المعلومات ديال التوجيه — منين جاي؟ لفين غادي؟ رقمو شحال؟
- **الـ Data** = المحتوى الحقيقي — الجزء ديال الرسالة اللي كانصيفطو.

بحال **الظرف ديال البريد**: الظرف عليه العنوان (Header) وداخلو الرسالة (Data).

---

## 7. كيفاش TCP كايقسم البيانات ؟

### المثال ديالنا الكامل

أحمد بغا يصيفط لسارة:

```
"Hello Sarah, how are you today?"
```

هاد الرسالة فيها **31 حرف** (31 Bytes). خلينا نفترضو بلي TCP قررّ يقسمها ل **3 Segments**:

```
الرسالة الأصلية:
"Hello Sarah, how are you today?"

         TCP كايقسمها:
         ┃
    ┌────┴─────────────────────────────────────┐
    │                                          │
    ▼                  ▼                       ▼

┌──────────────┐ ┌──────────────┐ ┌──────────────────┐
│  Segment #1  │ │  Segment #2  │ │   Segment #3     │
│  Seq: 1      │ │  Seq: 2      │ │   Seq: 3         │
│              │ │              │ │                   │
│ "Hello Sarah │ │ ", how are y"│ │ "ou today?"       │
│              │ │              │ │                   │
└──────────────┘ └──────────────┘ └──────────────────┘
     12 Bytes        12 Bytes          10 Bytes
```

كل Segment عندو:
- **Sequence Number** = الرقم ديالو باش الطرف الآخر يعرف الترتيب
- **Data** = جزء من الرسالة الأصلية

**ملاحظة:** الأرقام الحقيقية ديال الـ Sequence Numbers فـ TCP هم أرقام ديال الـ Bytes (مثلاً Byte 1, Byte 13, Byte 25...) ولكن هنا غادي نبسطوها بأرقام 1, 2, 3 باش يسهل الفهم.

---

## 8. كيفاش الـ Packets كايمشيو عبر الـ Routers ؟

هنا الشي المثير: كل Packet كايسافر **بشكل مستقل**. ما كايتسناش خوتو.

كل Router كايشوف العنوان اللي فالـ Header وكايقرر: "هاد الـ Packet خاصو يمشي من هاد الجيهة."

```
أحمد (المرسل)                                      سارة (المستقبل)
192.168.1.10                                        85.214.47.23

    │                                                    ▲
    │ كايصيفط 3 Segments                                 │
    │                                                    │
    ▼                                                    │
┌────────┐         ┌────────┐          ┌────────┐       │
│Router A│─────────│Router C│──────────│Router E│───────┘
└────────┘         └────────┘          └────────┘
    │                                      ▲
    │              ┌────────┐              │
    └──────────────│Router B│──────────────┘
                   └────────┘
                       │
                   ┌────────┐
                   │Router D│
                   └────────┘


  Segment #1:  أحمد → Router A → Router C → Router E → سارة
  Segment #2:  أحمد → Router A → Router B → Router E → سارة
  Segment #3:  أحمد → Router A → Router C → Router E → سارة
```

**شوف مزيان:** Segment #2 مشى فطريق مختلف عن #1 و #3! كل Router كايختار أحسن طريق **فداك اللحظة** حسب الزحمة ديال الشبكة.

---

## 9. علاش الـ Packets يقدرو يوصلو بترتيب غلط ؟

بما أن كل Packet كايمشي فطريقو، ممكن يوصلو **بترتيب مختلف** عن اللي تصيفطو بيه:

```
الترتيب اللي تصيفطو بيه:        الترتيب اللي وصلو بيه:
                                 
    1 ──►                            2  (وصل الأول!)
    2 ──►          الإنترنت          3  (وصل الثاني!)
    3 ──►                            1  (وصل الأخير!)
```

**علاش وقع هاد الشي ؟**

```
┌────────────────────────────────────────────────────────────┐
│                                                            │
│  Segment #1: مشى فطريق طويل عبر Router C → D → E         │
│              ← الطريق فيه زحمة → تأخر                     │
│                                                            │
│  Segment #2: مشى فطريق قصير عبر Router B → E              │
│              ← الطريق فارغ → وصل بكري                     │
│                                                            │
│  Segment #3: مشى فطريق متوسط عبر Router C → E             │
│              ← وصل قبل #1                                  │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

بحال 3 ديال السيارات اللي خرجو فنفس الوقت ولكن كل وحدة خدات طريق مختلف — اللي خدات الأوطوروت الفارغ وصلات قبل اللي دخلات للمدينة.

**واش هاد الشي مشكل ؟** لا! حيت TCP عندو حل — الـ **Sequence Numbers**.

## 10. كيفاش الـ Sequence Numbers كايخدمو ؟

الـ **Sequence Number** هو الرقم اللي TCP كايعطي لكل Segment باش المستقبل يعرف **الترتيب الصحيح**.

### خلينا نكملو المثال ديالنا:

سارة استقبلات الـ Segments بهاد الترتيب:

```
الترتيب ديال الوصول:

  ┌──────────────┐
  │  Segment #2  │  ← وصل الأول
  │  Seq: 2      │
  │ ", how are y"│
  └──────────────┘

  ┌──────────────────┐
  │   Segment #3     │  ← وصل الثاني
  │   Seq: 3         │
  │  "ou today?"     │
  └──────────────────┘

  ┌──────────────┐
  │  Segment #1  │  ← وصل الأخير
  │  Seq: 1      │
  │ "Hello Sarah"│
  └──────────────┘
```

سارة (يعني TCP عند سارة) كايشوف الـ Sequence Numbers وكايرتب:

```
قبل الترتيب:           بعد الترتيب:

  #2 ", how are y"       #1 "Hello Sarah"    ✅
  #3 "ou today?"         #2 ", how are y"    ✅
  #1 "Hello Sarah"       #3 "ou today?"      ✅
```

**النتيجة:** الرسالة كاملة وبالترتيب الصحيح!

```
 الرسالة المعاد بناؤها:
 ┌─────────────────────────────────────┐
 │  "Hello Sarah, how are you today?" │
 │                                     │
 │  ✅ كاملة    ✅ بالترتيب            │
 └─────────────────────────────────────┘
```

### شنو كايدير TCP ملي كايستقبل Segment ؟

```
وصل Segment #2 (ولكن #1 مازال ما وصلش)

  TCP عند سارة كايفكر:

  "عندي #2 ولكن ما عنديش #1 بعدا.
   غادي نحتافظ بـ #2 فالـ Buffer
   ونتسنى #1 باش نعطي الرسالة كاملة للبرنامج."

  Buffer:
  ┌──────┬──────────────┬──────────────────┐
  │  #1  │     #2       │      #3          │
  │  ❓  │ ", how are y"│  "ou today?"     │
  │فارغ! │   ✅ وصل    │    ✅ وصل       │
  └──────┴──────────────┴──────────────────┘
                │
                ▼
        كايتسنى #1...

  ────── وصل #1! ──────

  Buffer:
  ┌──────────────┬──────────────┬──────────────────┐
  │     #1       │     #2       │      #3          │
  │"Hello Sarah" │ ", how are y"│  "ou today?"     │
  │   ✅ وصل   │   ✅ وصل    │    ✅ وصل       │
  └──────────────┴──────────────┴──────────────────┘
                        │
                        ▼
         ✅ الرسالة كاملة! كاتوصل للبرنامج
```

## 11. كيفاش الـ ACK (Acknowledgment) كايخدم ؟

الـ **ACK** هو رسالة قصيرة كايصيفطها المستقبل للمرسل باش يقول ليه: **"وصلني!"**

### المثال ديالنا مع الـ ACKs:

```
  أحمد (المرسل)                               سارة (المستقبل)
      │                                            │
      │ ═══ Segment #1: "Hello Sarah" ══════════► │
      │                                            │  ← وصلني!
      │ ◄──────────────── ACK #1 ───────────────── │
      │                                            │
      │ ═══ Segment #2: ", how are y" ══════════► │
      │                                            │  ← وصلني!
      │ ◄──────────────── ACK #2 ───────────────── │
      │                                            │
      │ ═══ Segment #3: "ou today?" ═══════════► │
      │                                            │  ← وصلني!
      │ ◄──────────────── ACK #3 ───────────────── │
      │                                            │
      │         ✅ كلشي وصل!                       │
```

**الـ ACK بحال إيصال الاستلام:** ملي كاتصيفط طرد بالبوسطة وكاتطلب "إيصال الاستلام" — ملي الطرف الآخر كايستقبل الطرد، كايوقع على ورقة وكاترجع ليك: "وصل!"

### التفاصيل ديال الـ ACK:

```
┌───────────────────────────────────────────────────┐
│                 كيفاش ACK كايخدم                   │
│                                                   │
│  1. أحمد كايصيفط Segment #1                       │
│  2. أحمد كايشعل Timer (ساعة رملية)                │
│  3. سارة كاتستقبل Segment #1                      │
│  4. سارة كاتصيفط ACK #1 لأحمد                    │
│  5. أحمد كايستقبل ACK #1                          │
│  6. أحمد كايعرف: "#1 وصل بسلام" ✅               │
│  7. أحمد كايطفي الـ Timer                         │
│  8. أحمد كايصيفط Segment #2                       │
│  ...                                              │
└───────────────────────────────────────────────────┘
```

**ملاحظة مهمة:** فالحقيقة، TCP ما كايتسناش الـ ACK باش يصيفط الـ Segment اللي بعدو. كايصيفط بزاف ديال الـ Segments فنفس الوقت (هاد الشي اسمو **Sliding Window**). ولكن المبدأ الأساسي هو نفسو: **كل Segment خاصو ACK**.

---

## 12. شنو كايوقع إلا تواضر واحد الـ Packet ؟

هاد الشي كايوقع فالواقع! الـ Packets يقدرو يتوضرو بسبب:
- زحمة فالشبكة (Router كايحذف Packets اللي ما عندوش بلاصة ليهم)
- خطأ فالكابل
- مشكل فشي Router

### المثال ديالنا — Segment #2 تواضر:

```
  أحمد (المرسل)                               سارة (المستقبل)
      │                                            │
      │ ═══ Segment #1: "Hello Sarah" ══════════► │
      │                                            │  ← وصلني!
      │ ◄──────────────── ACK #1 ───────────────── │
      │                                            │
      │ ═══ Segment #2: ", how are y" ═══╳         │
      │                                  ╳         │
      │             💥 تواضر فالطريق!    ╳         │
      │                                            │
      │ ═══ Segment #3: "ou today?" ═══════════► │
      │                                            │
      │                                            │
      │    ⏰ Timer ديال Segment #2                │
      │    كايدور... كايدور...                      │
      │    ⏰💥 الوقت ساليتّ! ما جاش ACK #2!       │
      │                                            │
      │    "Segment #2 يبان توضر..."               │
      │                                            │
```

أحمد كايتسنى الـ ACK ديال Segment #2. ملي الـ Timer كايسالي بلا ما يجي ACK، أحمد كايعرف: **"#2 تواضر!"**

## 13. كيفاش الـ Retransmission كايخدم ؟

ملي أحمد عرف بلي Segment #2 تواضر (ما جاش ACK)، كايعاود يصيفطو:

```
  أحمد (المرسل)                               سارة (المستقبل)
      │                                            │
      │  "#2 ما وصلش... غادي نعاود نصيفطو"        │
      │                                            │
      │ ═══ Segment #2: ", how are y" ══════════► │
      │                 (إعادة الإرسال!)            │  ← هاد المرة وصلني!
      │                                            │
      │ ◄──────────────── ACK #2 ───────────────── │
      │                                            │
      │  ✅ "#2 وصل هاد المرة!"                    │
```

### الصورة الكاملة ديال المثال مع الـ Retransmission:

```
  أحمد                                              سارة
    │                                                  │
    │ ══ #1: "Hello Sarah" ══════════════════════════► │ ✅
    │ ◄───────────── ACK #1 ────────────────────────── │
    │                                                  │
    │ ══ #2: ", how are y" ═══╳  💥 ضاع!              │ ❌
    │                                                  │
    │ ══ #3: "ou today?" ═══════════════════════════► │ ✅
    │ ◄───────────── ACK #3 ────────────────────────── │
    │                                                  │
    │ ⏰ Timer #2 سالى! ما جاش ACK #2!                │
    │                                                  │
    │ ══ #2: ", how are y" ══════════════════════════► │ ✅ (Retransmission)
    │ ◄───────────── ACK #2 ────────────────────────── │
    │                                                  │
    │ ✅ كلشي وصل!                                     │ ✅ كلشي وصل!
    │                                                  │
    │                                Buffer ديال سارة: │
    │                                #1 ✅ #2 ✅ #3 ✅ │
    │                                                  │
    │                          "Hello Sarah, how are   │
    │                           you today?"            │
    │                           ✅ الرسالة كاملة!       │
```

## 14. كيفاش TCP كايضمن Reliable Delivery ؟

TCP عندو **4 ميكانيزمات** باش يضمن بلي البيانات كاتوصل:

```
┌──────────────────────────────────────────────────────────────┐
│              الـ 4 ضمانات ديال TCP                            │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │  1. SEQUENCE NUMBERS (الترقيم)                         │  │
│  │     كل Segment عندو رقم ← المستقبل كايعرف الترتيب     │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │  2. ACKNOWLEDGMENTS (التأكيد)                          │  │
│  │     المستقبل كايصيفط ACK لكل Segment ← المرسل كايعرف   │  │
│  │     بلي وصل                                            │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │  3. TIMERS (المؤقتات)                                  │  │
│  │     المرسل كايشعل Timer لكل Segment. إلا ما جاش ACK   │  │
│  │     قبل ما يسالي الوقت ← كايعرف بلي تواضر             │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │  4. RETRANSMISSION (إعادة الإرسال)                     │  │
│  │     إلا تواضر شي Segment، المرسل كايعاود يصيفطو       │  │
│  │     حتى يوصل                                           │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                              │
│  هاد الـ 4 مع بعضياتهم = ✅ Reliable Delivery               │
└──────────────────────────────────────────────────────────────┘
```

**ملخص بسيط:**

```
المرسل كايصيفط ← كايتسنى ACK ← ما جاش ACK ← كايعاود يصيفط ← كايتسنى ACK...
                                    │
                              ← جا ACK ← ✅ وصل! ← كايزيد للـ Segment اللي بعدو
```

## 15. كيفاش TCP كايعاود يبني الرسالة الأصلية ؟

عند المستقبل (سارة)، TCP كايدير هاد الخطوات:

```
الخطوة 1: كايستقبل الـ Segments (بأي ترتيب)
══════════════════════════════════════════

   وصل #3: "ou today?"
   وصل #1: "Hello Sarah"
   وصل #2: ", how are y"    (بعد الـ Retransmission)


الخطوة 2: كايرتب حسب الـ Sequence Numbers
══════════════════════════════════════════

   #1: "Hello Sarah"
   #2: ", how are y"
   #3: "ou today?"


الخطوة 3: كايلصق الأجزاء مع بعضياتهم
══════════════════════════════════════════

   ┌──────────────┬──────────────┬──────────────────┐
   │     #1       │     #2       │      #3          │
   │"Hello Sarah" │", how are y" │"ou today?"       │
   └──────┬───────┴──────┬───────┴────────┬─────────┘
          │              │                │
          └──────────────┼────────────────┘
                         │
                         ▼
         "Hello Sarah, how are you today?"


الخطوة 4: كايعطي الرسالة الكاملة للبرنامج
══════════════════════════════════════════

   TCP ──► البرنامج ديال سارة: "Hello Sarah, how are you today?"

   البرنامج ما كايعرف والو على الـ Packets، والترتيب، والضياع.
   كايشوف غير الرسالة الكاملة والنهائية. ✅
```

## 16. علاش البرامج ما كايحسوش بضياع الـ Packets ؟

هاد النقطة مهمة بزاف:

```
┌──────────────────────────────────────────────────────────┐
│                                                          │
│   ┌──────────────┐                                       │
│   │  البرنامج    │  ← كايشوف غير: "Hello Sarah, how     │
│   │  (IRC Client │     are you today?"                   │
│   │   ولا Server)│  ← ما كايعرفش بلي كانو Packets       │
│   └──────┬───────┘  ← ما كايعرفش بلي واحد تواضر         │
│          │          ← ما كايعرفش بلي وصلو بالقلوب        │
│          │                                               │
│          │  recv()                                        │
│          │                                               │
│   ┌──────┴───────┐                                       │
│   │     TCP      │  ← هو اللي كايدير الخدمة كاملة:       │
│   │   (النظام)   │     التقسيم، الترقيم، الـ ACK،        │
│   │              │     الـ Retransmission، الترتيب،       │
│   └──────┬───────┘     إعادة البناء                       │
│          │                                               │
│          │                                               │
│   ┌──────┴───────┐                                       │
│   │   الشبكة     │  ← الكوابل والـ Routers               │
│   └──────────────┘                                       │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

**TCP كايلعب دور الوسيط الذكي:**
- البرنامج كايعطي TCP الرسالة كاملة ← TCP كايقسمها وكايصيفطها.
- الشبكة كاتوصل الـ Packets ← TCP كايجمعهم وكايعطي البرنامج الرسالة كاملة.
- البرنامج **ما عمرو ما كايتعامل مع الـ Packets مباشرة**.

بحال ملي كاتصيفط طرد بـ DHL:
- نتا كاتعطيهم الطرد الكبير.
- DHL كايقسمو ويصيفطو وإلا تواضر شي جزء كايتبعو.
- الطرف الآخر كايستقبل الطرد الكبير كامل.
- ما عمرو ما كايعرف بلي تقسم ولا تواضر شي جزء.

## 17. علاش IRC كايعتمد على TCP ؟

ف IRC، كل كلمة مهمة وكل أمر خاصو يوصل:

```
┌──────────────────────────────────────────────────────────┐
│             علاش IRC ما يقدرش يخدم بلا TCP               │
│                                                          │
│  الأمر: "KICK ahmed"                                     │
│                                                          │
│  مع TCP:                                                 │
│  ✅ "KICK ahmed" كايوصل كامل وبالترتيب                   │
│  ✅ أحمد كايتطرد من الغرفة                               │
│  ✅ كلشي مزيان                                           │
│                                                          │
│  بلا TCP (مع UDP مثلاً):                                 │
│  ❌ الأمر يقدر يتوضر ← أحمد كايبقى فالغرفة             │
│  ❌ يقدر يوصل "ahmed KICK" ← ما كايتفهمش               │
│  ❌ يقدر يوصل "KIC" بلا "K" ← ناقص!                    │
│                                                          │
│  ═══════════════════════════════════════                  │
│                                                          │
│  الرسالة: "PRIVMSG #darija :Hello!\r\n"                  │
│                                                          │
│  مع TCP:                                                 │
│  ✅ الرسالة كاتوصل كاملة لكل واحد فالـ Channel           │
│  ✅ الناس كايشوفو الهضرة بالترتيب الصحيح                │
│                                                          │
│  بلا TCP:                                                │
│  ❌ شي ناس يقدرو ما يشوفوش الرسالة                     │
│  ❌ الرسائل يقدرو يوصلو بترتيب غلط                     │
│  ❌ ما يمكنش تعرف واش الرسالة وصلات                     │
│                                                          │
│  ═══════════════════════════════════════                  │
│                                                          │
│  أوامر الـ Authentication:                                │
│  "PASS mypassword\r\n"                                   │
│  "NICK ahmed\r\n"                                        │
│  "USER ahmed 0 * :Ahmed\r\n"                             │
│                                                          │
│  مع TCP:                                                 │
│  ✅ كايوصلو بالترتيب: PASS ← NICK ← USER               │
│  ✅ الـ Server كايعالجهم بالترتيب الصحيح                 │
│                                                          │
│  بلا TCP:                                                │
│  ❌ يقدر يوصل USER قبل PASS ← الـ Server ما كايقبلش     │
│  ❌ الـ Authentication كاتفشل                            │
└──────────────────────────────────────────────────────────┘
```

**الخلاصة:** IRC هو Protocol ديال الدردشة والأوامر — كل حرف مهم وكل ترتيب مهم. **TCP هو الوحيد** اللي كايضمن هاد الشي.

# Real-Life Analogy

## 📚 إرسال كتاب عبر البوسطة — صفحة صفحة

تخايل أحمد عندو كتاب من **30 صفحة** وبغا يصيفطو لسارة عبر البوسطة. ولكن المشكل: **الظرف صغير** وما يقدرش يدير فيه 30 صفحة فمرة وحدة.

### الخطوة 1: الترقيم (Sequence Numbers)

```
أحمد كايرقم كل صفحة:

  ┌─────────┐  ┌─────────┐  ┌─────────┐       ┌─────────┐
  │ صفحة 1  │  │ صفحة 2  │  │ صفحة 3  │  ...  │ صفحة 30 │
  │ من 30   │  │ من 30   │  │ من 30   │       │ من 30   │
  └─────────┘  └─────────┘  └─────────┘       └─────────┘
```

**= TCP كايعطي Sequence Number لكل Segment**

### الخطوة 2: الإرسال (Sending)

```
أحمد كايدير كل صفحة فظرف وكايصيفطها:

  ┌──────────────┐
  │  ✉️ ظرف #1   │ ──► البوسطة
  │  صفحة 1      │
  │  من: أحمد    │
  │  إلى: سارة  │
  └──────────────┘

  ┌──────────────┐
  │  ✉️ ظرف #2   │ ──► البوسطة
  │  صفحة 2      │
  │  من: أحمد    │
  │  إلى: سارة  │
  └──────────────┘

  ... (30 ظرف)
```

**= TCP كايقسم البيانات لـ Segments وكايصيفطهم**

### الخطوة 3: الطرقان المختلفين (Different Routes)

```
  ✉️ #1  ──► طريق A (الطريق السيار) ──► سارة      وصل بكري ✅
  ✉️ #2  ──► طريق B (المدينة)       ──► سارة      تأخر شوية ✅
  ✉️ #3  ──► طريق A                 ──► 💥 تواضر!  ❌
  ✉️ #4  ──► طريق C (ريفي)          ──► سارة      وصل ✅
```

**= الـ Packets كايمشيو عبر Routers مختلفين**

### الخطوة 4: إيصال الاستلام (ACK)

```
سارة كاتستقبل الظروف وكاتصيفط إيصال لأحمد:

  سارة ──► "وصلني ظرف #1" ──► أحمد    (ACK #1) ✅
  سارة ──► "وصلني ظرف #2" ──► أحمد    (ACK #2) ✅
  سارة ──►                             ما صيفطاتش ACK #3
  سارة ──► "وصلني ظرف #4" ──► أحمد    (ACK #4) ✅
```

**= المستقبل كايصيفط ACK لكل Segment**

### الخطوة 5: إعادة الإرسال (Retransmission)

```
  أحمد كايشوف: "#3 ما جاش الإيصال ديالو... يبان تواضر"

  أحمد ──► كايعاود يصيفط ظرف #3 ──► سارة
  سارة ──► "وصلني ظرف #3!" ──► أحمد    (ACK #3) ✅
```

**= TCP كايعاود يصيفط الـ Segments اللي تواضرو**

### الخطوة 6: إعادة البناء (Reassembly)

```
  سارة عندها 30 ظرف، ولكن وصلو بهاد الترتيب:
    #1, #4, #2, #7, #3, #5, ...

  سارة كاترتب الصفحات حسب الأرقام:
    #1, #2, #3, #4, #5, #6, #7, ... #30

  سارة كاتحط الصفحات مع بعضياتهم:
    ┌─────────────────────────┐
    │      📖 الكتاب كامل     │
    │    30 صفحة بالترتيب     │
    │         ✅               │
    └─────────────────────────┘
```

**= TCP كايرتب الـ Segments وكايبني الرسالة الأصلية**

### الخريطة ديال التشبيه:

```
┌─────────────────────────────────────────────────────────────┐
│   الحياة الواقعية            │      TCP                     │
│─────────────────────────────────────────────────────────────│
│   📖 الكتاب                  │   الرسالة الكاملة            │
│   📄 الصفحة                  │   الـ Segment (Packet)       │
│   ✉️ الظرف                   │   الـ Packet مع الـ Header   │
│   📝 رقم الصفحة              │   الـ Sequence Number        │
│   🏤 البوسطة                 │   الـ Network (الشبكة)      │
│   🚚 سيارة التوزيع           │   الـ Router                │
│   🛣️ الطرقان المختلفين       │   الـ Routes فالإنترنت      │
│   📬 إيصال الاستلام          │   الـ ACK                   │
│   ⏰ المدة ديال الانتظار     │   الـ Timer (Timeout)       │
│   🔄 إعادة إرسال الظرف       │   الـ Retransmission        │
│   📚 تجميع الكتاب            │   الـ Reassembly            │
│   🤷 سارة ما كاتعرفش بالمشاكل│   البرنامج ما كايحسش       │
│                              │   بالـ Packets               │
└─────────────────────────────────────────────────────────────┘
```

# Key Takeaways

```
┌──────────────────────────────────────────────────────────────────┐
│                    النقاط الأساسية                                │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1. الـ Network هي أجهزة متصلين مع بعضياتهم عبر Routers         │
│     وكوابل باش يتبادلو المعلومات.                                │
│                                                                  │
│  2. كل جهاز عندو IP Address فريد = العنوان ديالو فالشبكة.       │
│     127.0.0.1 = "أنا راسي" (localhost).                         │
│                                                                  │
│  3. الـ Port = رقم الباب. كل خدمة فالجهاز عندها Port خاص.      │
│     IP + Port = العنوان الكامل.                                  │
│                                                                  │
│  4. البيانات ما يمكنش تتصيفط ككتلة وحدة كبيرة بسبب حدود        │
│     الشبكة والمرونة والأمان.                                     │
│                                                                  │
│  5. TCP كايقسم البيانات لـ Segments صغار وكايعطي لكل             │
│     واحد Sequence Number.                                        │
│                                                                  │
│  6. الـ Segments كايمشيو عبر Routers مختلفين ويقدرو يوصلو       │
│     بترتيب غلط.                                                  │
│                                                                  │
│  7. المستقبل كايصيفط ACK لكل Segment باش المرسل يعرف            │
│     بلي وصل.                                                     │
│                                                                  │
│  8. إلا ما جاش ACK (Timer سالى)، المرسل كايعاود يصيفط           │
│     الـ Segment = Retransmission.                                │
│                                                                  │
│  9. المستقبل كايرتب الـ Segments حسب Sequence Numbers            │
│     وكايبني الرسالة الأصلية.                                     │
│                                                                  │
│  10. البرنامج (بحال IRC Server) ما كايحسش بالـ Packets ولا       │
│      بالضياع ولا بالترتيب — TCP كايدير كلشي فالخلف.             │
│                                                                  │
│  11. IRC خاصو TCP حيت كل كلمة وكل أمر وكل ترتيب مهم.           │
```

# Common Beginner Mistakes

### ❌ الخطأ 1: "الرسالة ديما كاتوصل ككتلة وحدة"

```
  ❌ الفكرة الغلط:
     أحمد كايصيفط "Hello Sarah" ← كاتوصل لسارة "Hello Sarah" فدقة وحدة

  ✅ الحقيقة:
     الرسالة كاتتقسم لـ Segments وكل واحد كايمشي بوحدو.
     عند المستقبل، TCP كايجمعهم. البرنامج كايشوف الرسالة كاملة
     ولكن فالشبكة، مشات مقسمة.
```

**علاش هاد الشي مهم ف ft_irc:** ملي الـ Server ديالك كايستعمل `recv()`، يقدر يستقبل جزء من الرسالة فقط — خاصك تتسنى باقي الأجزاء.

---

### ❌ الخطأ 2: "الـ Packets ديما كايوصلو بالترتيب"

```
  ❌ الفكرة الغلط:
     إلا صيفطت #1 قبل #2 قبل #3، ديما غادي يوصلو 1 → 2 → 3

  ✅ الحقيقة:
     كل Packet كايمشي فطريقو الخاص. يقدرو يوصلو:
     3 → 1 → 2  ولا  2 → 3 → 1  ولا أي ترتيب آخر.

     TCP كايرتبهم عند المستقبل بفضل الـ Sequence Numbers.
```

---

### ❌ الخطأ 3: "TCP ما عمرو ما كايخسر Packets"

```
  ❌ الفكرة الغلط:
     TCP موثوق = ما كاين حتى Packet كايتوضر

  ✅ الحقيقة:
     الـ Packets كايتوضرو فالشبكة!
     TCP "موثوق" حيت كايكتاشف الضياع (بالـ Timer والـ ACK)
     وكايعاود يصيفط اللي تواضر (Retransmission).

     TCP ما كايمنعش الضياع — كايصلّح الضياع.
```

---

### ❌ الخطأ 4: "TCP هو الإنترنت"

```
  ❌ الفكرة الغلط:
     TCP = الإنترنت

  ✅ الحقيقة:
     TCP هو غير طبقة واحدة من بزاف ديال الطبقات:

     Application (IRC, HTTP...)  ← البرنامج
     Transport (TCP, UDP)        ← الضمانة والتقسيم
     Internet (IP)               ← التوجيه
     Network Access (Ethernet)   ← الكوابل والـ WiFi

     الإنترنت هو **المجموعة ديال هاد الطبقات** مع بعضياتهم.
```

---

### ❌ الخطأ 5: "البرنامج كايستقبل الـ Packets مباشرة"

```
  ❌ الفكرة الغلط:
     IRC Server كايشوف الـ Packets وكايجمعهم بيدو

  ✅ الحقيقة:
     البرنامج ما كايشوف حتى Packet.
     TCP (فالـ Operating System) كايدير كلشي:
       - كايستقبل الـ Packets
       - كايرتبهم
       - كايجمعهم
       - كايعطي البرنامج Stream ديال الـ Bytes

     البرنامج كايشوف غير "تدفق" ديال الـ Bytes — بلا حدود ديال
     الـ Packets.

     ⚠️ ولكن هاد الشي فيه مشكل آخر: البرنامج خاصو يعرف
     فين رسالة IRC سالات ← يعني يلقى \r\n
```

# Self-Check Questions

**جاوب على هاد الأسئلة بالدارجة ولا بالإنجليزية. ما تجاوبش حتى تكون فاهم الدرس كامل:**

> **1.** أحمد بغا يصيفط رسالة طويلة لسارة. علاش TCP ما كايصيفطهاش ككتلة وحدة ؟ عطي 3 أسباب.

> **2.** كل Segment عندو Sequence Number. شنو الدور ديال هاد الرقم ؟ شنو غادي يوقع بلاه ؟

> **3.** أحمد صيفط 4 Segments. سارة استقبلات #1, #3, #4 ولكن #2 ما وصلش. صف بالتفصيل شنو غادي يوقع دابا — عند أحمد وعند سارة.

> **4.** شنو هو الـ ACK ؟ شكون اللي كايصيفطو ؟ ولشكون ؟ وعلاش كايصيفطو ؟

> **5.** شنو الفرق بين "TCP ما عمرو ما كايخسر Packets" و"TCP كايضمن Reliable Delivery" ؟ علاش الجملة الأولى غلط والثانية صحيحة ؟

> **6.** أحمد عندو IP Address `192.168.1.10` والـ Server ديال سارة على Port `6667`. أحمد بغا يتصل. شنو العنوان الكامل اللي خاصو يستعمل ؟ علاش خاصو الاثنين مع بعضياتهم ؟

> **7.** شنو هو `127.0.0.1` ؟ وعلاش غادي تستعملو بزاف فالتجارب ديال ft_irc ؟

> **8.** ف IRC، شنو غادي يوقع إلا الأمر `KICK ahmed` وصل مقسم ل `"KIC"` و `"K ahmed\r\n"` ؟ واش هاد الشي مشكل ؟ شكون اللي خاصو يتعامل معاه ؟

> **9.** تخايل أحمد صيفط 3 Segments وكل واحد مشى فطريق مختلف. Segment #3 وصل قبل #1. واش سارة (البرنامج ديالها) غادي تشوف الرسالة بالترتيب الغلط ؟ علاش ؟

> **10.** شنو الفرق الأساسي بين الـ Header والـ Data فالـ Packet ؟ عطي مثال واقعي بالظرف ديال البوسطة.

---
