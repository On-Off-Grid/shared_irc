# 📚 الدرس 2: كيفاش الأجهزة كايتواصلو — Networking و TCP

## Goal

> تفهم كيفاش جهازين كايتواصلو عبر الإنترنت: شنو هو الـ IP Address، شنو هو الـ Port، شنو هو الـ TCP، وكيفاش كايخدمو مع بعضياتهم باش الرسائل توصل من الـ Client للـ Server.

---

## Explanation

### 1. كيفاش جهازين كايتواصلو فالإنترنت ؟

باش جهازين يتواصلو، خاصهم **3 حاجات أساسية:**

| الحاجة | الشرح بالدارجة |
|---|---|
| **IP Address** | العنوان ديال الجهاز — فين ساكن فالإنترنت |
| **Port** | رقم الباب — شمن خدمة بغيت نوصل ليها فهاداك الجهاز |
| **Protocol** | القانون اللي كايتبعو باش يفهمو بعضياتهم (TCP ولا UDP) |

بلا هاد 3، ما يمكنش يوقع أي تواصل.

---

### 2. شنو هو الـ IP Address ؟

الـ **IP Address** هو العنوان ديال الجهاز فالشبكة. بحال عنوان الدار: إلا بغيت تصيفط بريد لشي واحد، خاصك تعرف فين ساكن.

كل جهاز متصل بالإنترنت عندو **IP Address** فريد. مثال:

```
192.168.1.10      ← عنوان ديال جهاز فالشبكة المحلية
127.0.0.1         ← عنوان خاص: كايعني "أنا راسي" (localhost)
```

**`127.0.0.1`** هو عنوان مهم بزاف بالنسبة لينا: ملي غادي تجرب الـ Server ديالك، غادي تشغلو على نفس الجهاز. يعني الـ Client والـ Server كايكونو فنفس الحاسوب، والعنوان ديالهم هو `127.0.0.1` ولا `localhost`.

---

### 3. شنو هو الـ Port ؟

الـ **Port** هو رقم الباب فالجهاز.

تخايل واحد العمارة (الجهاز) فيها بزاف ديال الشقق (الخدمات). العنوان ديال العمارة هو الـ IP Address، ولكن باش توصل للشقة الصحيحة، خاصك رقم الشقة — وهاداك هو الـ **Port**.

```
IP Address = العنوان ديال العمارة
Port       = رقم الشقة فالعمارة
```

أمثلة ديال الـ Ports المعروفين:

| Port | الخدمة |
|---|---|
| `80` | HTTP (المواقع العادية) |
| `443` | HTTPS (المواقع الآمنة) |
| `6667` | IRC (الـ Default Port ديال IRC) |
| `22` | SSH |

ف ft_irc، نتا اللي كاتختار الـ Port ملي كاتشغل الـ Server:

```
./ircserv 6667 mypassword
         ^^^^
         هاذا هو الـ Port
```

**ملاحظات مهمة على الـ Ports:**
- الـ Ports من `0` لـ `1023` = **Well-known Ports** — محجوزين للنظام (خاصك Root باش تستعملهم).
- الـ Ports من `1024` لـ `65535` = تقدر تستعملهم بلا مشكل.
- جهاز واحد يقدر يشغل بزاف ديال الخدمات فنفس الوقت، كل وحدة فـ Port مختلف.

---

### 4. IP Address + Port = العنوان الكامل

باش تتصل بشي خدمة، خاصك الـ IP Address **و** الـ Port مع بعضياتهم. هاد الثنائي اسمو **Socket Address**:

```
┌─────────────────────────────────┐
│     Socket Address الكامل       │
│                                 │
│   IP Address  :  Port           │
│   192.168.1.5 :  6667           │
│                                 │
│   = "الجهاز X، الباب 6667"      │
└─────────────────────────────────┘
```

بحال ملي كاتقول: "سير لعمارة رقم 5 فشارع محمد الخامس، الشقة رقم 6667."

بلا الـ IP → ما تعرفش فين الجهاز.
بلا الـ Port → توصل للجهاز ولكن ما تعرفش شمن باب تدق.

---

### 5. شنو هو الـ Protocol ؟

الـ **Protocol** هو مجموعة ديال القواعد اللي كاتقول كيفاش جوج طرفين يتفاهمو.

بحال ملي كاتهضر فالتيليفون:
- كاتقول "ألو" ← الطرف الآخر كايقول "ألو"
- كاتسول السؤال ← كايجاوبك
- ملي تسالي كاتقول "بسلامة" ← كايقول "بسلامة"

هاد القواعد هي الـ Protocol ديال المكالمة. بلا هاد القواعد، كل واحد غادي يهضر كيفما بغا والآخر ما غادي يفهم والو.

ف Networking، عندنا بزاف ديال الـ Protocols، ولكن أهم جوج هم:

| Protocol | الخاصية |
|---|---|
| **TCP** | موثوق — كايضمن بلي الرسالة توصل كاملة وبالترتيب |
| **UDP** | سريع — ولكن ما كايضمنش والو |

---

### 6. شنو هو TCP بالتفصيل ؟

**TCP** = **Transmission Control Protocol**

TCP هو الـ Protocol اللي كايضمن بلي البيانات كاتوصل **كاملة**، **بالترتيب**، و**بلا أخطاء**.

#### كيفاش TCP كايبدا الاتصال ؟ — الـ 3-Way Handshake

قبل ما يبدا أي تواصل، TCP كايدير واحد الطقوس اسمو **3-Way Handshake** — بحال التحية قبل ما تبدا تهضر:

```
Client                          Server
  │                                │
  │ ──── 1. SYN ─────────────────► │   "سلام، واش نقدر نتصل ؟"
  │                                │
  │ ◄──── 2. SYN-ACK ──────────── │   "سلام، أه تفضل"
  │                                │
  │ ──── 3. ACK ─────────────────► │   "شكراً، ها أنا متصل"
  │                                │
  │      ✅ الاتصال مفتوح          │
  │      🔄 تقدرو تبداو تهضرو     │
```

- **SYN** = Synchronize = "بغيت نتصل"
- **SYN-ACK** = "وصلني الطلب ديالك، مرحبا"
- **ACK** = Acknowledge = "وصلني، شكراً"

**ملاحظة مهمة:** هاد الـ Handshake كايوقع **أوتوماتيكياً** ملي كاتستعمل الـ Sockets. ما غاديش تبرمجو يدوياً — الـ Operating System كايديرو بلاصتك.

---

### 7. شنو كايوقع بعد الاتصال ؟ — إرسال البيانات

من بعد الـ Handshake، الاتصال مفتوح وتقدرو تبداو تصيفطو البيانات:

```
Client                          Server
  │                                │
  │ ── "NICK ahmed\r\n" ────────► │   الـ Client كايصيفط اسمو
  │                                │
  │ ◄── ":server 001 ahmed" ───── │   الـ Server كايرد عليه
  │                                │
  │ ── "JOIN #darija\r\n" ──────► │   كايطلب يدخل لغرفة
  │                                │
  │ ◄── ":ahmed JOIN #darija" ─── │   الـ Server كايأكد
  │                                │
```

كل رسالة ف IRC كاتسالي بـ **`\r\n`** (يعني Return + Newline). هاد الشي هو اللي كايعلم الـ Server بلي الرسالة كملات.

---

### 8. TCP كـ Stream — علاش الرسائل يقدرو يوصلو مقسمين ؟

واحد النقطة مهمة بزاف: TCP هو **Stream Protocol** — يعني كايشوف البيانات بحال واحد "النهر" ديال الـ Bytes كايسيل بلا حدود واضحة.

TCP **ما كايعرفش** شنو هي "الرسالة". هو غير كايوصل الـ Bytes. نتا اللي خاصك تعرف فين رسالة بدات وفين سالات.

مثال:

```
┌─────────────────────────────────────────────────┐
│             شنو صيفط الـ Client                  │
│                                                 │
│  "NICK ahmed\r\nJOIN #darija\r\n"               │
│   ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^              │
│   جوج رسائل IRC فنفس الوقت                      │
└─────────────────────────────────────────────────┘

ولكن TCP يقدر يوصلهم هكذا:

  وصول 1:  "NICK ahm"         ← ناقصة!
  وصول 2:  "ed\r\nJOIN"       ← فيها نهاية الأولى وبداية الثانية!
  وصول 3:  " #darija\r\n"     ← الباقي

ولا هكذا:

  وصول 1:  "NICK ahmed\r\nJOIN #darija\r\n"   ← كلشي مرة وحدة

ولا هكذا:

  وصول 1:  "N"
  وصول 2:  "I"
  وصول 3:  "CK ahmed\r\nJOIN #dari"
  وصول 4:  "ja\r\n"
```

**هاد الشي هو اللي خاصك تفهم مزيان:**
- TCP كايضمن بلي الـ Bytes كايوصلو **بالترتيب** و**بلا ضياع**.
- ولكن TCP **ما كايضمنش** بلي كل `recv()` غادي يعطيك رسالة كاملة.
- خاصك تبني **Buffer** لكل Client باش تجمع الـ Bytes حتى تلقى `\r\n`.

---

### 9. TCP vs UDP — علاش TCP وماشي UDP ؟

| الخاصية | TCP | UDP |
|---|---|---|
| **الاتصال** | كاين (3-Way Handshake) | ما كاينش |
| **الضمانة** | ✅ كايضمن الوصول | ❌ ما كايضمنش |
| **الترتيب** | ✅ بالترتيب | ❌ يقدر يتخربق |
| **السرعة** | أبطأ شوية | أسرع |
| **الاستعمال** | Chat, Web, Email, IRC | Games, Video, DNS |

**علاش IRC خاصو TCP؟**

تخايل كاترسل الأمر `KICK ahmed` (طرد أحمد):
- **مع TCP**: الأمر كايوصل كامل وبالترتيب ← أحمد كايتطرد ✅
- **مع UDP**: الأمر يقدر يتوضر ← أحمد كايبقى ❌
- ولا يوصل مقلوب `ahmed KICK` ← الـ Server ما كايفهموش ❌

**ف IRC، كل كلمة مهمة وكل أمر خاصو يوصل. ولهاد السبب، TCP هو الخيار الوحيد.**

---

### 10. الـ Network Layers — النظرة العامة

ما غاديش ندخلو فالتفاصيل، ولكن خاصك تعرف بلي الشبكة مبنية على **طبقات** (Layers):

```
┌──────────────────────────────────────────────┐
│  الطبقة 4: Application Layer                 │
│  ← هنا فين كاين IRC Protocol                │
│  ← الرسائل بحال "NICK ahmed\r\n"            │
├──────────────────────────────────────────────┤
│  الطبقة 3: Transport Layer                   │
│  ← هنا فين كاين TCP                         │
│  ← كايقسم البيانات لـ Segments               │
│  ← كايضمن الوصول والترتيب                    │
├──────────────────────────────────────────────┤
│  الطبقة 2: Internet Layer                    │
│  ← هنا فين كاين IP                          │
│  ← كايختار الطريق من جهاز لجهاز             │
├──────────────────────────────────────────────┤
│  الطبقة 1: Network Access Layer             │
│  ← الكوابل، الـ WiFi، الـ Hardware           │
└──────────────────────────────────────────────┘
```

**ف ft_irc، نتا كاتخدم فالطبقة 4 (Application Layer):**
- كاتكتب الـ IRC Protocol
- كاتستعمل TCP (الطبقة 3) من خلال الـ Sockets
- الـ Operating System كايتكلف بالباقي (IP, Hardware...)

### 11. ملخص المسار الكامل ديال رسالة

من اللحظة اللي أحمد كايكتب الرسالة حتى كاتوصل لسارة:

```
أحمد كايكتب "Hello!" فالـ Client ديالو
         │
         ▼
┌─────────────────────────────────────┐
│ 1. الـ Client كايحول الرسالة لصيغة  │
│    IRC: "PRIVMSG #darija :Hello!\r\n"│
└────────────────┬────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────┐
│ 2. TCP كايقسم الرسالة لـ Segments    │
│    وكايصيفطها عبر الشبكة            │
└────────────────┬────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────┐
│ 3. الـ Server كايستقبل الـ Bytes     │
│    عبر recv() وكايجمعهم فالـ Buffer │
└────────────────┬────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────┐
│ 4. ملي كايلقى \r\n ← عرف بلي      │
│    الرسالة كاملة ← كايعالجها        │
└────────────────┬────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────┐
│ 5. الـ Server كايشوف شكون ف #darija │
│    ← سارة ✅ ← كايصيفط ليها         │
│    ← أحمد (المرسل) ← ما يصيفطش     │
└────────────────┬────────────────────┘
                 │
                 ▼
سارة كاتشوف: ":ahmed PRIVMSG #darija :Hello!"
```

## ASCII Diagrams

### الفرق بين IP و Port

```
      ┌───────────────── الجهاز (العمارة) ─────────────────┐
      │  IP Address: 192.168.1.5                           │
      │                                                    │
      │  ┌──────────┐  ┌──────────┐  ┌──────────┐        │
      │  │ Port 22  │  │ Port 80  │  │ Port 6667│        │
      │  │  (SSH)   │  │  (HTTP)  │  │  (IRC)   │        │
      │  │  شقة 22  │  │  شقة 80  │  │ شقة 6667 │        │
      │  └──────────┘  └──────────┘  └──────────┘        │
      └────────────────────────────────────────────────────┘
```

### الـ 3-Way Handshake

```
    Client                              Server
      │                                    │
      │ ─────── SYN ─────────────────────► │
      │         "واش نقدر نتصل؟"           │
      │                                    │
      │ ◄─────── SYN-ACK ──────────────── │
      │          "أه، تفضل"                │
      │                                    │
      │ ─────── ACK ─────────────────────► │
      │         "شكراً، تصلنا"             │
      │                                    │
      │ ════════════════════════════════════│
      │     ✅ Connection Established       │
      │     🔄 دابا تقدرو تهضرو           │
```

### الـ Buffer وتجميع الرسائل

```
recv() #1:  "NICK ahm"        →  Buffer: [NICK ahm]
                                          ما كاينش \r\n ← كمّل تسنا

recv() #2:  "ed\r\nJOI"       →  Buffer: [NICK ahmed\r\n|JOI]
                                          ┗━━ لقينا \r\n! ━━┛
                                          ← عالج "NICK ahmed"
                                          ← بقا "JOI" فالـ Buffer

recv() #3:  "N #darija\r\n"   →  Buffer: [JOIN #darija\r\n]
                                          ┗━━ لقينا \r\n! ━━┛
                                          ← عالج "JOIN #darija"
                                          ← الـ Buffer فارغ ✅
```

## Real-Life Example

### 📞 المكالمة الهاتفية

تخايل كاتتصل بشي واحد فالتيليفون:

| الخطوة فالتيليفون | المقابل ف TCP |
|---|---|
| تعرف رقم الهاتف ديال الشخص | تعرف الـ **IP Address** ديال الـ Server |
| تعرف رقم الإمتداد (Extension) ديال المكتب | تعرف الـ **Port** |
| كاتدق ← كايرن ← كايرفع ← "ألو" | الـ **3-Way Handshake** (SYN → SYN-ACK → ACK) |
| كاتهضر وكاتسمع | الـ **Data Transfer** عبر `send()` و `recv()` |
| كل واحد كايتسنى الآخر يكمل قبل ما يجاوب | **الترتيب** اللي TCP كايضمنو |
| إلا ما سمعش مزيان كايقول "عاود عليا" | TCP كايعاود يصيفط الـ Packet اللي ما وصلش (**Retransmission**) |
| كاتقول "بسلامة" وكاترشي | **Connection Close** (FIN → ACK) |

**الفرق مع UDP:** UDP بحال ملي كاتصيفط رسالة صوتية (Voice Message): كاتصيفطها وما كاتعرفش واش وصلات، واش سمعها، ولا واش فهمها. ولهاد السبب ما يصلحش لـ IRC.

## Key Takeaways

1. **IP Address** = عنوان الجهاز فالشبكة. `127.0.0.1` = "أنا راسي" (localhost).
2. **Port** = رقم الباب فالجهاز. كل خدمة عندها Port خاص بيها.
3. **IP + Port** = العنوان الكامل (Socket Address) باش توصل لخدمة معينة فجهاز معين.
4. **Protocol** = القواعد ديال التواصل. TCP = موثوق. UDP = سريع ولكن ما كايضمنش.
5. **3-Way Handshake** = SYN → SYN-ACK → ACK. كايوقع أوتوماتيكياً قبل أي اتصال TCP.
6. **TCP = Stream** — ما كايعرفش حدود الرسائل. نتا اللي خاصك تلقى `\r\n` باش تعرف فين سالات الرسالة.
7. **Buffer** = خاصك تجمع الـ Bytes فمساحة مؤقتة حتى تكمل الرسالة.
8. ف ft_irc، كاتخدم فالـ **Application Layer** وكاتستعمل TCP من خلال الـ Sockets.
9. الـ **Operating System** كايتكلف بالطبقات السفلية (IP, Hardware).
10. **كل رسالة IRC كاتسالي بـ `\r\n`** — هاد الشي هو الفاصل بين الرسائل.

## Common Beginner Mistakes

| ❌ الخطأ | ✅ الصواب |
|---|---|
| كايفكرو بلي `recv()` كايرجع رسالة IRC كاملة | `recv()` كايرجع **Bytes** — يقدرو يكونو ناقصين ولا فيهم بزاف ديال الرسائل |
| كايتجاهلو الـ Buffer | **خاصك** Buffer لكل Client باش تجمع الـ Bytes حتى تلقى `\r\n` |
| كايخلطو بين الـ Port والـ IP Address | IP = الجهاز، Port = الخدمة فداك الجهاز. خاصك الاثنين |
| كايستعملو Ports تحت 1024 بلا Root | الـ Ports من 0 لـ 1023 محجوزين — استعمل Port فوق 1024 |
| كايفكرو بلي خاصهم يبرمجو الـ 3-Way Handshake | الـ OS كايديرها أوتوماتيكياً — نتا غير كاتستعمل `connect()` و `accept()` |
| كايفكرو بلي TCP و IRC هو نفس الشي | TCP = طبقة النقل. IRC = طبقة التطبيق. IRC كايخدم **فوق** TCP |

## Self-Check Questions

**جاوب على هاد الأسئلة بالدارجة ولا بالإنجليزية — بحالما بغيتي:**

> **1.** إلا الـ Server ديالك كايخدم على `127.0.0.1:6667`، شنو كايعني `127.0.0.1` ؟ وشنو كايعني `6667` ؟ وعلاش كاتحتاجهم بجوج ؟

> **2.** الـ Client صيفط `"NICK ahmed\r\nJOIN #darija\r\n"` ولكن `recv()` عطاتك غير `"NICK ahm"`. واش هاد الشي عادي ؟ شنو خاصك تدير ؟

> **3.** شنو هو الـ 3-Way Handshake ؟ وواش خاصك تبرمجو بيديك ف ft_irc ؟

> **4.** شنو الفرق الأساسي بين TCP و UDP ؟ وعطي مثال واحد فين TCP أحسن ومثال فين UDP أحسن.

> **5.** علاش كل رسالة IRC خاصها تسالي بـ `\r\n` ؟ شنو غادي يوقع إلا ما كانش هاد الفاصل ؟
