## 1. المقدمة (Introduction) <a name="1-المقدمة"></a>

### شنو هي Phase 2؟

Phase 2 هي المرحلة اللي فيها غادي نبداو نبنيو **الأساس الحقيقي ديال الـ Server**: الشبكة.

فـ Phase 1، بنينا الهيكل ديال المشروع — الـ `Makefile`، الـ `Server` class، الـ `main.cpp`. كان كولشي skeleton فارغ بلا روح. ما كان حتى اتصال، ما كان حتى client، ما كان والو.

دابا فـ Phase 2، غادي نعطيو الروح لهاد الـ Server. غادي نخليوه **يسمع** على الشبكة، يقبل الاتصالات، ويتسنى الـ clients.

### علاش الشبكة هي أول حاجة نيمبلومونطيو؟

تخيل بغيت تبني مطعم. قبل ما تبدا تطيب ولا تجيب الطبلات، خاصك **تحل الباب ديال المطعم**. إيلا ما حليتيش الباب، حتى واحد ما غادي يدخل.

نفس الحاجة مع الـ IRC server:
- ما تقدرش تعالج الـ IRC commands (بحال `NICK` ولا `JOIN`) إيلا ما كانش عندك clients
- ما يقدرش يكون عندك clients إيلا ما عندكش اتصال شبكي
- ما يقدرش يكون عندك اتصال شبكي إيلا ما عندكش **Socket**

يعني الترتيب المنطقي هو:

```
Socket → Connection → Client → Parser → Commands
```

ما تقدرش تبدا من النص. خاصك تبدا من **الأساس**.

### علاش ما نقدروش نبداو بالـ IRC commands قبل الـ Sockets؟

الـ IRC commands (بحال `NICK`, `USER`, `JOIN`, `PRIVMSG`) كيحتاجو **client يكون متصل**. والـ client باش يتصل خاصو **socket يكون خدام**. بلا socket، ما كاين حتى اتصال. بلا اتصال، ما كاين حتى client. بلا client، ما كاين حتى command.

> **القاعدة:** الـ Socket هو الأساس. بلا أساس، ما تبنيش.

### كيفاش كيتواصل الـ User مع الـ Server؟

قبل ما ندخلو فالتفاصيل، خاصنا نشوفو الصورة الكبيرة. شنو كيوقع ملي شي واحد كيبغي يدخل لقناة IRC؟

```
┌──────────────────────────────────────────────────────────────┐
│                    مسار الاتصال الكامل                        │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│    ┌────────────┐                                            │
│    │    User     │  ← المستخدم اللي بغا يهضر                │
│    └─────┬──────┘                                            │
│          │                                                   │
│          ▼                                                   │
│    ┌────────────┐                                            │
│    │ IRC Client  │  ← البرنامج اللي كيستعملو (irssi, WeeChat)│
│    └─────┬──────┘                                            │
│          │                                                   │
│          ▼                                                   │
│    ┌────────────┐                                            │
│    │    TCP      │  ← البروتوكول اللي كيضمن التوصيل         │
│    └─────┬──────┘                                            │
│          │                                                   │
│          ▼                                                   │
│    ┌────────────┐                                            │
│    │  Internet   │  ← الشبكة (ولا localhost)                 │
│    └─────┬──────┘                                            │
│          │                                                   │
│          ▼                                                   │
│    ┌────────────────┐                                        │
│    │Listening Socket │  ← الباب ديال الـ Server              │
│    └─────┬──────────┘                                        │
│          │                                                   │
│          ▼                                                   │
│    ┌────────────┐                                            │
│    │ IRC Server  │  ← البرنامج ديالنا (ft_irc)              │
│    └────────────┘                                            │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### شرح كل مرحلة:

| المرحلة | الشرح |
|---|---|
| **User** | الإنسان اللي بغا يستعمل الـ IRC. كيكتب الرسائل وكيقرا الأجوبة |
| **IRC Client** | البرنامج اللي كيستعملو الـ User (بحال `irssi` ولا `WeeChat` ولا `nc`). هو اللي كيحول اللي كيكتبو الـ User لرسائل IRC |
| **TCP** | البروتوكول ديال الـ Transport Layer. كيضمن بلي الرسالة كتوصل كاملة ومرتبة |
| **Internet** | الشبكة اللي كتربط الـ Client بالـ Server. يقدر يكون الإنترنت الحقيقي ولا `localhost` (نفس الجهاز) |
| **Listening Socket** | الباب الرئيسي ديال الـ Server. كيتسنى الاتصالات الجديدة. هادا هو اللي غادي نبنيوه فهاد الـ Phase |
| **IRC Server** | البرنامج ديالنا (`ft_irc`). كيقبل الاتصالات، كيعالج الرسائل، وكيرد على الـ Clients |

### شنو غادي نبنيو فهاد الـ Phase بالضبط؟

فهاد الـ Phase، غادي نبنيو **غير الـ Listening Socket**. يعني غادي نوصلو للنقطة فين الـ Server كيتسنى الاتصالات، ولكن ما غاديش نقبلو حتى اتصال بعد.

```
هاد الـ Phase كيغطي:
───────────────────
    socket()
    setsockopt()
    fcntl()
    bind()
    listen()
    ← هنا كنوقفو

ما كيغطيش:
───────────────────
    accept()      ← Phase الجاية
    poll()        ← Phase الجاية
    recv()/send() ← Phase الجاية
```

## 3. شنو هو الـ Socket؟ <a name="3-شنو-هو-الـ-socket"></a>

### التعريف (Definition)

**Socket** هو **نقطة نهاية ديال الاتصال** (Communication Endpoint). هو المكان اللي فيه البرنامج كيتصل بالشبكة.

بعبارة بسيطة: الـ Socket هو الباب اللي كيخلي البرنامج ديالك يبعث ويستقبل البيانات عبر الشبكة.

ملي كتسمع كلمة "Socket"، فكر فيها بحال الپريز ديال الضو فالحيط. الپريز (Socket) هو المكان اللي كتوصل فيه الجهاز ديالك بالكهرباء. بنفس الطريقة، الـ Network Socket هو المكان اللي كيتوصل فيه البرنامج بالشبكة.

### نقطة نهاية ديال الاتصال (Communication Endpoint)

كل اتصال شبكي عندو **جوج أطراف**:
- الطرف اللي كيبعث
- الطرف اللي كيستقبل

كل طرف عندو الـ Socket ديالو. يعني:
- الـ Client عندو Socket واحد
- الـ Server عندو Socket واحد (ولا بزاف)
- الاتصال كيكون بين Socket ديال الـ Client و Socket ديال الـ Server

```
┌──────────────┐                    ┌──────────────┐
│   Client      │                    │    Server     │
│               │                    │               │
│  ┌─────────┐  │    الاتصال         │  ┌─────────┐  │
│  │ Socket  │──┼────────────────────┼──│ Socket  │  │
│  └─────────┘  │                    │  └─────────┘  │
│               │                    │               │
└──────────────┘                    └──────────────┘
```

### علاش كاينين الـ Sockets؟

البرنامج ديالك (process) كيخدم فـ **user space**. الشبكة كتخدم فـ **kernel space**. البرنامج ما يقدرش يبعث packets مباشرة على الشبكة — خاصو يمر عبر الـ Operating System.

الـ Socket هو **الجسر** بين البرنامج والـ OS:

```
┌────────────────────────────────────────────┐
│              User Space                     │
│                                            │
│    ┌──────────────────┐                    │
│    │   البرنامج ديالك  │                    │
│    │   (ft_irc)        │                    │
│    └────────┬─────────┘                    │
│             │                              │
│             │ socket()                     │
│             ▼                              │
├─────────── الـ Socket ───────────────────── │
│             │                              │
│             ▼                              │
│    ┌──────────────────┐                    │
│    │     Kernel        │                    │
│    │  (TCP/IP Stack)   │                    │
│    └────────┬─────────┘                    │
│             │                              │
│             ▼                              │
│    ┌──────────────────┐                    │
│    │   Network Card    │                    │
│    │   (NIC)           │                    │
│    └──────────────────┘                    │
│              Kernel Space                   │
└────────────────────────────────────────────┘
```

بلا الـ Socket، البرنامج ما يقدرش يتواصل مع الشبكة. الـ Socket هو الواسيط بين عالم البرنامج وعالم الشبكة.

### العلاقة بين البرنامج والـ Operating System

ملي البرنامج ديالك كيعيط لـ `socket()`، الـ OS كيدير بزاف ديال الخدمة:

1. كيخلق **كائن Socket** (Socket Object) فالـ Kernel
2. كيخصص **الذاكرة** للـ Buffers ديال الإرسال والاستقبال
3. كيربط الـ Socket بالـ **TCP/IP stack**
4. كيعطيك **رقم** (File Descriptor) باش تقدر تتحكم فيه

أنت ما كتشوفش هاد التفاصيل. كتشوف غير **رقم** (بحال `3` ولا `4`). ولكن وراه، كاين عالم كامل.

### الفرق بين البرنامج والشبكة

| البرنامج | الشبكة |
|---|---|
| كيخدم فالـ RAM | كيخدم فالـ Wire (الكابل) |
| كيتعامل مع Variables و Functions | كيتعامل مع Packets و Protocols |
| كيخدم فـ User Space | كيخدم فـ Kernel Space |
| سريع بزاف | بطيء نسبياً |
| موثوق | ممكن تضيع البيانات |

الـ Socket هو اللي كيحول بين هاد العالمين. كيحول الـ `send()` ديالك لـ TCP packets، وكيحول الـ TCP packets اللي وصلات لداتا اللي تقدر تقراها بـ `recv()`.

```
┌──────────────────────────────────────────────┐

│                                              │
│    ┌────────────────────────────┐             │
│    │                            │             │
│    │    الصالون = الـ Logic      │             │
│    │    (معالجة الرسائل)        │             │
│    │                            │             │
│    └────────────────────────────┘             │
│                                              │
│    ╔════════════════╗                        │
│    ║   الباب        ║ ← هادا هو الـ Socket   │

│    ╚═══════╤════════╝                        │
│            │                                 │
│            ▼                                 │
```

- **الدار** = البرنامج ديالك
- **الباب** = الـ Socket
- **الشارع** = الشبكة
- **الناس اللي كيدقو** = الـ Clients

بلا باب، الناس ما يقدروش يدخلو لعندك. بلا Socket، الـ Clients ما يقدروش يتصلو بالـ Server.

#### 📞 تشبيه التيليفون

```
   أنت                                    صاحبك
    │                                       │
    ▼                                       ▼
┌────────┐                           ┌────────┐
│ هاتفك  │ ←──── خط التيليفون ────→ │ هاتفو  │
│(Socket)│                           │(Socket)│
└────────┘                           └────────┘
```

- كل واحد عندو **هاتف** (Socket)
- **خط التيليفون** = الاتصال TCP
- **رقم التيليفون** = الـ IP Address + Port
- **الهضرة** = البيانات اللي كيتبادلو

ملي كتعيط لشي واحد:
1. كتدق عليه (تبعث SYN)
2. كيرد عليك (كيبعث SYN-ACK)
3. كتبدا تهضر (ACK — الاتصال تأسس)

هادا هو بالضبط الـ **TCP Three-Way Handshake**.

#### 🏨 تشبيه الأوطيل

```
┌─────────────────────────────────────────┐
│              الأوطيل (Server)            │
│                                         │
│    ┌──────────────────────┐             │
│    │  الاستقبال (Reception) │ ← listen() │
│    │  = Listening Socket   │             │
│    └──────────┬───────────┘             │
│               │                         │
│     accept()  │                         │
│               ▼                         │
│    ┌──────────────────────┐             │
│    │  الغرفة 1 (Room 1)   │ ← Client 1  │
│    │  = Client Socket 1   │             │
│    ├──────────────────────┤             │
│    │  الغرفة 2 (Room 2)   │ ← Client 2  │
│    │  = Client Socket 2   │             │
│    ├──────────────────────┤             │
│    │  الغرفة 3 (Room 3)   │ ← Client 3  │
│    │  = Client Socket 3   │             │
│    └──────────────────────┘             │
│                                         │
└─────────────────────────────────────────┘
```

- **الأوطيل** = الـ Server
- **الاستقبال** (Reception) = الـ Listening Socket — كيتسنى الناس الجداد
- **الغرف** = الـ Client Sockets — كل client عندو Socket خاص بيه
- **الموظف ديال الاستقبال** = `accept()` — كيقبل الناس وكيعطيهم غرفهم

الاستقبال (Listening Socket) ما كيتسد أبداً — ديما كيتسنى ناس جداد. الغرف كيتفتحو وكيتسدو حسب الـ Clients.

#### 📮 تشبيه البوسطة (Post Office)

```
   المرسل (Client)           المستقبل (Server)
       │                          │
       ▼                          ▼
  ┌─────────┐               ┌──────────┐
  │ صندوق   │               │ صندوق    │
  │ البريد  │──── البوسطة ──→│ البريد   │
  │ (Socket)│               │ (Socket) │
  └─────────┘               └──────────┘
```

- **صندوق البريد** = الـ Socket
- **العنوان** = الـ IP Address
- **رقم الشقة** = الـ Port
- **البوسطة** (Postal Service) = الـ TCP/IP
- **البريات** (Letters) = الـ Packets

الفرق: فالبوسطة، ما كتعرفش واش البرية وصلات. فالـ TCP، **كتعرف** حيت كيكون عندك تأكيد (Acknowledgement).

| المفهوم | الشرح |

## 4. شنو هو الـ TCP؟ <a name="4-شنو-هو-الـ-tcp"></a>

### التعريف (Definition)

**TCP** (Transmission Control Protocol) هو **بروتوكول ديال النقل** اللي كيضمن بلي البيانات كتوصل كاملة، مرتبة، وبلا أخطاء.

**IP** (Internet Protocol) هو البروتوكول اللي كيضمن بلي الـ Packets كيعرفو الطريق ديالهم — يعني كيتصلو من الـ Source للـ Destination.

TCP و IP كيخدمو مع بعضياتهم: الـ IP كيدوز الـ Packets، والـ TCP كيضمن بلي وصلو كاملين ومرتبين.

### تشبيه واقعي

تخيل بغيت تبعث كتاب لصاحبك، ولكن الكتاب كبير بزاف. ما يقدرش يتبعث فبرية وحدة.

**بلا TCP (UDP):**
- كتقطع الكتاب لصفحات وكل صفحة كتبعثها فبرية
- ممكن شي صفحات توصل قبل الأخرى
- ممكن شي صفحات تضيع
- صاحبك خاصو يحاول يجمعهم بوحدو

**مع TCP:**
- كتقطع الكتاب لصفحات **مرقمة**
- كل صفحة كتبعثها وكتتسنى **التأكيد** (Acknowledgement)
- إيلا ما وصلش التأكيد، كتعاود تبعثها
- صاحبك كيجمعهم **بالترتيب** حيت مرقمين
- فالآخر، عندو الكتاب كامل بلا ما تنقص حتى صفحة

### الـ Packets (الحزم)

البيانات ما كتتبعثش دفعة وحدة عبر الشبكة. كتتقطع لقطع صغيرة اسمها **Packets**.

```
الرسالة الأصلية:
"NICK Ayoub\r\n"

ممكن تتقسم لـ Packets هكا:

┌─────────┐  ┌─────────┐  ┌─────────┐
│ Packet 1 │  │ Packet 2 │  │ Packet 3 │
│ "NIC"    │  │ "K Ay"   │  │ "oub\r\n"│
│ Seq: 1   │  │ Seq: 2   │  │ Seq: 3   │
└─────────┘  └─────────┘  └─────────┘
```

> **ملاحظة:** فالحقيقة، رسالة قصيرة بحال هادي عادةً كتمشي فـ Packet واحد. ولكن الرسائل الطويلة كتتقسم.

### الاتصال الموثوق (Reliable Communication)

TCP كيضمن هاد الأشياء:

| الخاصية | الشرح |
|---|---|
| **Reliable Delivery** | كل Packet كيوصل — إيلا تضيعت كتتبعث مرة أخرى |
| **Ordered** | الـ Packets كيوصلو بالترتيب اللي تبعثو بيه |
| **Error-Checked** | كل Packet عندها Checksum باش تتأكد بلي ما فيهاش أخطاء |
| **Connection-Oriented** | خاص الاتصال يتأسس قبل ما تبدا تبعث |
| **Flow Control** | ما كيبعثش بيانات أكثر مما يقدر يستقبل الطرف الآخر |

### التأكيدات (Acknowledgements)

```
Client                               Server
  │                                     │
  │──── Packet 1 (Seq=100) ────────────→│
  │                                     │
  │←──── ACK (Ack=101) ────────────────│   ✓ وصل
  │                                     │
  │──── Packet 2 (Seq=101) ────────────→│
  │                                     │
  │         ✗ تضيعت فالطريق            │
  │                                     │
  │     (ما وصلش ACK... كنتسنى...)     │
  │                                     │
  │──── Packet 2 (Seq=101) ────────────→│   إعادة الإرسال
  │                                     │
  │←──── ACK (Ack=102) ────────────────│   ✓ وصلات هاد المرة
  │                                     │
```

كل Packet كتبعثها، كتتسنى تأكيد (ACK) من الطرف الآخر. إيلا ما وصلش التأكيد فوقت معين (Timeout)، كتعاود تبعث الـ Packet. هادا هو **Retransmission**.

### الترتيب (Ordering)

حتى إيلا وصلات الـ Packets بترتيب غالط، TCP كيردهم للترتيب الصحيح:

```
كتبعث:       Packet 1, Packet 2, Packet 3
كيوصلو:      Packet 3, Packet 1, Packet 2  (مخلطين)
TCP كيردهم:   Packet 1, Packet 2, Packet 3  (مرتبين)
```

هادشي كيوقع حيت كل Packet عندها **رقم تسلسلي** (Sequence Number). TCP كيستعمل هاد الرقم باش يرتبهم.

### إعادة الإرسال (Retransmission)

```
┌───────────────────────────────────────────────┐
│           إعادة الإرسال (Retransmission)        │
├───────────────────────────────────────────────┤
│                                               │
│  1. بعث Packet                                │
│  2. بدا Timer                                 │
│  3. واش وصل ACK؟                             │
│     │                                         │
│     ├── نعم → مزيان، بعث اللي بعدها          │
│     │                                         │
│     └── لا (Timeout) → عاود بعث نفس Packet   │
│                                               │
│  إيلا فشل بزاف ديال المرات → سد الاتصال     │
│                                               │
└───────────────────────────────────────────────┘
```

### علاش IRC كيستعمل TCP بدل UDP؟

| TCP | UDP |
|---|---|
| **موثوق** — كل رسالة كتوصل | **ما موثوقش** — ممكن تضيع |
| **مرتب** — الرسائل كيوصلو بالترتيب | **ما مرتبش** — يقدرو يوصلو مخلطين |
| **Connection-Oriented** — كاين اتصال | **Connectionless** — ما كاين اتصال |
| **أبطأ شوية** | **أسرع** |

الـ IRC خاصو **TCP** حيت:
- ما تقدرش تضيع رسالة. إيلا شي واحد كتب `/kick User`، خاص الأمر يوصل
- ما تقدرش تخلط الترتيب. الـ `NICK` خاص يجي قبل `USER`
- خاصك تعرف واش الـ Client مزال متصل ولا لا

الـ UDP مزيان لحوايج بحال الألعاب ولا streaming فين السرعة أهم من الموثوقية. ولكن IRC خاصو الموثوقية.

### كيفاش الـ Packets كيسافرو؟

```
┌──────────┐                              ┌──────────┐
│  Client   │                              │  Server   │
│           │                              │           │
│ Application│                              │Application│
│ ┌────────┐│                              │┌────────┐│
│ │"NICK"  ││                              ││البيانات ││
│ └───┬────┘│                              │└────────┘│
│     │     │                              │    ▲     │
│     ▼     │                              │    │     │
│ ┌────────┐│                              │┌────────┐│
│ │  TCP   ││  Packet + Header             ││  TCP   ││
│ │+ Header││─────────────────────────────→││ Reassem││
│ └───┬────┘│                              │└───┬────┘│
│     │     │                              │    │     │
│     ▼     │                              │    ▲     │
│ ┌────────┐│     الشبكة (Network)         │┌────────┐│
│ │   IP   ││─────────────────────────────→││   IP   ││
│ └────────┘│                              │└────────┘│
│           │                              │           │
└──────────┘                              └──────────┘
```

1. البرنامج كيعطي البيانات للـ TCP
2. TCP كيضيف الـ Header ديالو (Port المصدر، Port الوجهة، Sequence Number...)
3. IP كيضيف الـ Header ديالو (IP المصدر، IP الوجهة...)
4. الـ Packet كتمشي عبر الشبكة
5. فالطرف الآخر، IP كيشيل الـ Header ديالو
6. TCP كيشيل الـ Header ديالو وكيرجع البيانات الأصلية
7. البرنامج كيستقبل البيانات

### شنو كيوقع إيلا وصلات الـ Packets مقطعة (Fragmented)؟

هادا مفهوم مهم بزاف فـ ft_irc. ملي كتبعث رسالة IRC بحال:

```
PRIVMSG #channel :السلام عليكم كيف داير\r\n
```

ممكن توصل **مقطعة** فعدة `recv()` calls:

```
recv() الأول:    "PRIVMSG #cha"
recv() الثاني:   "nnel :السلام"
recv() الثالث:   " عليكم كيف داير\r\n"
```

ولا ممكن رسالتين يوصلو **مجموعين** فـ `recv()` واحد:

```
recv() واحد:    "NICK Ayoub\r\nUSER ayoub 0 * :Ayoub\r\n"
```

هادشي حيت TCP هو **stream protocol** — ما كيعرفش حدود الرسائل. هو غير كيبعث bytes. الـ Application (البرنامج ديالنا) هو اللي خاصو يلقى حدود الرسائل (فحالة IRC، الـ `\r\n`).

> **هاد المشكل غادي يتعامل معاه Souhail فالـ Buffer Manager.** ولكن خاصك تفهمو باش تعرف علاش كاين.

### ملخص

| المفهوم | الشرح |
|---|---|
| TCP | بروتوكول نقل موثوق، مرتب، بتأكيدات |
| IP | بروتوكول كيوجه الـ Packets للوجهة ديالهم |
| Packets | قطع صغيرة ديال البيانات |
| ACK | تأكيد بلي الـ Packet وصل |
| Retransmission | إعادة إرسال الـ Packet إيلا ما وصلش التأكيد |
| Stream Protocol | TCP ما كيعرفش حدود الرسائل |

## 5. الـ File Descriptor <a name="5-الـ-file-descriptor"></a>

### التعريف (Definition)

**File Descriptor** (FD) هو **رقم صحيح** (integer) اللي الـ Operating System كيعطيه للبرنامج باش يمثل **مورد مفتوح** (Open Resource).

فـ Linux، كل حاجة هي **ملف**: الملفات العادية، الـ Pipes، الـ Terminals، و**الـ Sockets**. كلهم كيتمثلو برقم — الـ File Descriptor.

### تشبيه واقعي

تخيل عندك مكتب فيه **أدراج** (Drawers). كل درج عندو رقم:
- الدرج 0 = الورق اللي كيوصلك (stdin)
- الدرج 1 = الورق اللي كتبعث (stdout)
- الدرج 2 = الورق ديال الأخطاء (stderr)
- الدرج 3 = أول حاجة جديدة فتحتيها
- الدرج 4 = ثاني حاجة...

الأرقام هادو هما الـ File Descriptors.

### علاش الأرقام؟

الـ Kernel كيحتفظ بجدول (Table) لكل Process. هاد الجدول فيه كل الـ File Descriptors المفتوحين:

```
┌───────────────────────────────────────────┐
│        File Descriptor Table               │
│        (ديال Process واحد)                 │
├──────┬────────────────────────────────────┤
│  FD  │            المورد                  │
├──────┼────────────────────────────────────┤
│  0   │  stdin   (الدخول — الكلافيي)      │
│  1   │  stdout  (الخروج — الشاشة)        │
│  2   │  stderr  (الأخطاء — الشاشة)       │
│  3   │  socket  (الـ Listening Socket)    │
│  4   │  socket  (Client 1)                │
│  5   │  socket  (Client 2)                │
│  6   │  file    (log.txt)                 │
└──────┴────────────────────────────────────┘
```

### كل حاجة فـ Linux هي ملف (Everything is a File)

هاد المبدأ هو من أساسيات Linux/Unix. كل حاجة — ملف عادي، directory، pipe، terminal، socket — كتتمثل بـ File Descriptor. هادشي كيخلي البرنامج يتعامل مع كلشي بنفس الطريقة:
- `read()` باش تقرا
- `write()` باش تكتب
- `close()` باش تسد

### stdin, stdout, stderr

كل Process ملي كيتخلق، كيكون عندو 3 ديال الـ File Descriptors مفتوحين بالأساس:

| FD | الاسم | الوظيفة | المصدر/الوجهة |
|---|---|---|---|
| 0 | `stdin` | Standard Input | الكلافيي (Keyboard) |
| 1 | `stdout` | Standard Output | الشاشة (Terminal) |
| 2 | `stderr` | Standard Error | الشاشة (Terminal) |

هادشي علاش ملي كتعيط لـ `socket()`، أول FD اللي كيعطيك هو **3** — حيت 0, 1, 2 مخوذين.

### الـ Socket FD

ملي كتعيط لـ `socket()`، الـ Kernel كيخلق Socket Object فالـ Kernel Space وكيعطيك FD (رقم) باش تتحكم فيه:

```
البرنامج ديالك                    الـ Kernel
─────────────────                ─────────────────

int fd = socket(...)    ───→    كيخلق Socket Object
                                كيضيف entry فالـ FD Table
fd = 3              ←───────    كيرجع الرقم 3
```

أنت ما كتشوفش الـ Socket Object. كتشوف غير الرقم `3`. وكل ملي بغيت تدير شي حاجة بالـ Socket، كتستعمل هاد الرقم:

```c++
bind(3, ...)      // ربط الـ Socket بعنوان
listen(3, ...)    // بدا الإنصات
accept(3, ...)    // قبل اتصال جديد
close(3)          // سد الـ Socket
```

### الملكية (Ownership)

الـ File Descriptor مملوك **للـ Process اللي خلقو**. ما يقدرش Process آخر يستعملو (إلا بطرق خاصة بحال `fork()`).

هادشي كيعني:
- الـ Server ديالك هو الوحيد اللي يقدر يستعمل الـ FD ديال الـ Listening Socket
- إيلا مات الـ Server (ولا عمل `close()`)، الـ FD كينتهي

### مدة الحياة (Lifetime)

الـ File Descriptor كيبقى حي من ملي **كتخلقو** حتى ملي:
1. **كتسدو بـ `close()`** — الطريقة الصحيحة
2. **كيموت الـ Process** — الـ OS كيسد كلشي أوتوماتيكياً

> ⚠️ **تحذير:** إيلا ما سديتيش الـ FD بـ `close()`، غادي يبقى مفتوح وكياخذ موارد. هادا هو **FD Leak** — مشكل خطير.

### ()close

`close()` كيدير:
1. كيسد الـ File Descriptor
2. كيحرر الموارد ديال الـ Kernel (الـ Socket Object, الـ Buffers...)
3. كيرجع الرقم ديال الـ FD متاح لاستعمال مرة أخرى

```c++
close(fd);  // ← ضروري تديرها ملي تسالي مع الـ Socket
```

### ملخص

| المفهوم | الشرح |
|---|---|
| File Descriptor | رقم كيمثل مورد مفتوح فالـ Kernel |
| stdin (0) | الدخول القياسي |
| stdout (1) | الخروج القياسي |
| stderr (2) | مخرج الأخطاء |
| Socket FD | FD خاص بالـ Socket — كيرجع من `socket()` |
| `close()` | كيسد الـ FD وكيحرر الموارد |

## 6. ()socket — إنشاء الـ Socket <a name="6-socket"></a>

### الغرض (Purpose)

`socket()` هي أول system call فبناء أي اتصال شبكي. الغرض ديالها بسيط: **خلق نقطة نهاية ديال الاتصال** (Communication Endpoint).

تخيلها بحال ملي كتشري تيليفون جديد. التيليفون مزال ما عندوش رقم (ما عملتيش `bind()`), وما مشعّلش باش يستقبل المكالمات (ما عملتيش `listen()`). ولكن عندك الجهاز — هادا هو اللي كيديرو `socket()`.

### تشبيه واقعي

```
socket() = شراء تيليفون جديد
bind()   = تسجيل رقم فيه
listen() = تشعلو وتتسنى المكالمات
accept() = ترد على مكالمة
```

فهاد القسم، غادي نتكلمو غير على `socket()` — شراء التيليفون.

### الـ Prototype

```c
int socket(int domain, int type, int protocol);
```

هادي هي الـ Function اللي الـ OS كيعطيك. خلينا نشرحو كل Parameter:

### الـ Parameters

#### 1. `domain` — عائلة العناوين (Address Family)

هاد الـ Parameter كيحدد **نوع العناوين** اللي غادي تستعمل:

| القيمة | المعنى | الاستعمال |
|---|---|---|
| `AF_INET` | IPv4 | الأكثر استعمالاً — هادا اللي غادي نستعملو |
| `AF_INET6` | IPv6 | العناوين الجديدة (128-bit) |
| `AF_UNIX` | Unix Domain | الاتصال المحلي بين Processes |

فـ ft_irc، كنستعملو **`AF_INET`** حيت كنخدمو بـ IPv4 (عناوين بحال `127.0.0.1`).

**AF** كتعني **Address Family** — يعني عائلة العناوين.

#### 2. `type` — نوع الـ Socket

هاد الـ Parameter كيحدد **كيفاش غادي يتواصل الـ Socket**:

| القيمة | المعنى | البروتوكول |
|---|---|---|
| `SOCK_STREAM` | Stream Socket — اتصال مستمر وموثوق | TCP |
| `SOCK_DGRAM` | Datagram Socket — رسائل منفصلة | UDP |
| `SOCK_RAW` | Raw Socket — وصول مباشر للـ Packets | خاص |

فـ ft_irc، كنستعملو **`SOCK_STREAM`** حيت بغينا **TCP** — اتصال موثوق ومرتب.

**SOCK_STREAM** كيعني: البيانات كتمشي بحال **نهر** (Stream) — مستمر، بالترتيب، بلا ما تنقص.

#### 3. `protocol` — البروتوكول

```
0  ← خلي الـ OS يختار البروتوكول المناسب
```

ملي كتحط `0`، الـ OS كيختار البروتوكول المناسب بناءً على `domain` و `type`:
- `AF_INET` + `SOCK_STREAM` + `0` = **TCP**
- `AF_INET` + `SOCK_DGRAM` + `0` = **UDP**

ما كاين حتى سبب تحط قيمة أخرى فـ ft_irc.

### شنو كيوقع داخل الـ Kernel؟

ملي البرنامج ديالك كيعيط لـ `socket(AF_INET, SOCK_STREAM, 0)`، هادا اللي كيوقع:

```
┌──────────────────────────────────────────────┐
│              البرنامج ديالك                    │
│                                              │
│   int fd = socket(AF_INET, SOCK_STREAM, 0);  │
│                    │                         │
│                    │  System Call             │
│                    ▼                         │
├──────────────────────────────────────────────┤
│              الـ Kernel                       │
│                                              │
│   1. كيخلق Socket Object جديد               │
│      ┌──────────────────────┐               │
│      │ Socket Object         │               │
│      │ ─ domain: AF_INET     │               │
│      │ ─ type: SOCK_STREAM   │               │
│      │ ─ protocol: TCP       │               │
│      │ ─ state: CREATED      │               │
│      │ ─ send_buffer: empty  │               │
│      │ ─ recv_buffer: empty  │               │
│      └──────────────────────┘               │
│                                              │
│   2. كيخصص Buffers (الإرسال + الاستقبال)    │
│                                              │
│   3. كيضيف entry فالـ FD Table               │
│      ┌──────┬───────────────┐               │
│      │  FD  │    Object      │               │
│      ├──────┼───────────────┤               │
│      │  0   │  stdin         │               │
│      │  1   │  stdout        │               │
│      │  2   │  stderr        │               │
│      │  3   │  Socket Object │ ← جديد!      │
│      └──────┴───────────────┘               │
│                                              │
│   4. كيرجع 3 للبرنامج                      │
│                                              │
└──────────────────────────────────────────────┘
```

### موارد الـ Kernel

كل Socket كياخذ موارد من الـ Kernel:

| المورد | الشرح |
|---|---|
| **Socket Object** | الهيكل اللي كيحتوي على كل المعلومات ديال الـ Socket |
| **Send Buffer** | مكان مؤقت للبيانات اللي غادي تتبعث |
| **Receive Buffer** | مكان مؤقت للبيانات اللي وصلات |
| **FD Entry** | مدخل فالجدول ديال الـ File Descriptors |
| **TCP State** | حالة الاتصال (CREATED, LISTENING, CONNECTED...) |

هادشي علاش **ضروري تسد الـ Socket بـ `close()`** — باش تحرر هاد الموارد.

### القيم اللي كترجع (Return Values)

| القيمة | المعنى |
|---|---|
| `>= 0` | **نجاح** — الرقم هو الـ File Descriptor ديال الـ Socket الجديد |
| `-1` | **فشل** — كاين مشكل. شوف `errno` باش تعرف شنو وقع |

أسباب الفشل الشائعة:

| الـ errno | المعنى |
|---|---|
| `EMFILE` | الـ Process وصل للحد الأقصى ديال الـ FDs المفتوحين |
| `ENFILE` | النظام كامل وصل للحد الأقصى ديال الـ FDs |
| `ENOMEM` | ما بقاتش ذاكرة كافية |
| `EACCES` | ما عندكش الصلاحيات |

### تخصيص الذاكرة (Memory Allocation)

ملي `socket()` كتنجح، الـ Kernel كيخصص ذاكرة لعدة حوايج:

```
الذاكرة اللي كتتخصص:
─────────────────────

┌─────────────────────────────┐
│     Socket Object            │ ← ~200 bytes
│  (المعلومات الأساسية)        │
├─────────────────────────────┤
│     Send Buffer              │ ← ~128 KB (default)
│  (للبيانات اللي غادي تتبعث) │
├─────────────────────────────┤
│     Receive Buffer           │ ← ~128 KB (default)
│  (للبيانات اللي غادي توصل)  │
├─────────────────────────────┤
│     TCP State Machine        │ ← حالة الاتصال
│  (SYN_SENT, ESTABLISHED...) │
└─────────────────────────────┘
```

> هاد الأرقام تقريبية وكتختلف حسب الـ OS.

### ملخص

| المفهوم | الشرح |
|---|---|
| `socket()` | كيخلق نقطة نهاية ديال الاتصال |
| `AF_INET` | IPv4 Address Family |
| `SOCK_STREAM` | TCP — اتصال موثوق |
| `protocol = 0` | خلي الـ OS يختار |
| Return value | FD (نجاح) ولا -1 (فشل) |
| Kernel resources | Socket Object + Buffers + FD Entry |

## 7. ()setsockopt — إعداد الـ Socket <a name="7-setsockopt"></a>

### المشكل: "Address already in use"

تخيل هاد السيناريو:
1. كتشغل الـ Server على Port 6667
2. الـ Server كيتسنى الاتصالات
3. كتوقف الـ Server (بـ `Ctrl+C` ولا crash)
4. كتحاول تشغلو مرة أخرى
5. **كيبان ليك الـ Error:** `bind: Address already in use`

### علاش كيوقع هادشي؟

ملي كتوقف الـ Server، الـ Kernel ما كيحررش الـ Port **فوراً**. كيبقى محجوز لمدة قصيرة (عادةً 60 ثانية ولا أكثر). هادا اسمو **TIME_WAIT state**.

الـ Kernel كيدير هادشي كإجراء أمان: باش يتأكد بلي الـ Packets القديمة اللي مزال كيدورو فالشبكة ما غاديش يتخلطو مع اتصال جديد.

```
الـ Server توقف → الـ Port مزال محجوز (TIME_WAIT)
       │
       │  60 ثانية ولا أكثر
       ▼
الـ Port تحرر → دابا تقدر تشغل الـ Server مرة أخرى
```

هاد المشكل كيحمقك ملي كتكون كتطور — كتوقف وكتشغل الـ Server بزاف ديال المرات.

### الحل: `SO_REUSEADDR`

`setsockopt()` مع `SO_REUSEADDR` كتقول للـ Kernel: **"سمح لي نستعمل هاد الـ Port حتى إيلا مزال فـ TIME_WAIT"**.

### الـ Prototype

```c
int setsockopt(int sockfd, int level, int optname,
               const void *optval, socklen_t optlen);
```

| Parameter | القيمة فـ ft_irc | المعنى |
|---|---|---|
| `sockfd` | الـ FD ديال الـ Socket | شنو الـ Socket اللي بغينا نعدلو عليه |
| `level` | `SOL_SOCKET` | مستوى الـ Option (Socket Level) |
| `optname` | `SO_REUSEADDR` | اسم الـ Option |
| `optval` | `&opt` (opt = 1) | القيمة (1 = فعّل) |
| `optlen` | `sizeof(opt)` | حجم القيمة |

### سلوك الـ Kernel

بلا `SO_REUSEADDR`:
```
bind() → الـ Kernel كيشوف الـ Port فـ TIME_WAIT → يرفض → Error!
```

مع `SO_REUSEADDR`:
```
bind() → الـ Kernel كيشوف الـ Port فـ TIME_WAIT → كيتجاهل → نجاح!
```

### الـ Socket Options

`SO_REUSEADDR` هو واحد من بزاف ديال الـ Socket Options. شي وحدين مهمين:

| Option | المعنى |
|---|---|
| `SO_REUSEADDR` | سمح بإعادة استعمال العنوان |
| `SO_REUSEPORT` | سمح بإعادة استعمال الـ Port (مختلف عن ADDR) |
| `SO_KEEPALIVE` | بعث رسائل باش تتأكد الاتصال مزال حي |
| `SO_RCVBUF` | حجم الـ Receive Buffer |
| `SO_SNDBUF` | حجم الـ Send Buffer |

فـ ft_irc، كنحتاجو غير **`SO_REUSEADDR`**.

### إمتا نعيطو لها؟

**بعد `socket()` وقبل `bind()`**:

```
socket()       ← 1. خلق الـ Socket
    │
    ▼
setsockopt()   ← 2. عدّل الإعدادات ديالو  ★ هنا
    │
    ▼
bind()         ← 3. ربطو بعنوان
```

إيلا عيطتي لها بعد `bind()`:
- `SO_REUSEADDR` ما غاديش يأثر — فات الوقت، الـ `bind()` مشات
- بعض الـ Options الأخرى يقدرو يخدمو بعد `bind()`، ولكن `SO_REUSEADDR` خاصو يكون **قبل**

### الأخطاء الشائعة

| الخطأ | النتيجة |
|---|---|
| نسيان `setsockopt()` نهائياً | "Address already in use" ملي كتعاود تشغل الـ Server |
| تعييطها بعد `bind()` | `SO_REUSEADDR` ما كيأثرش |
| `opt = 0` بدل `opt = 1` | كتعطل الـ Option بدل ما تفعلها |
| نسيان `&opt` (الـ Pointer) | Segfault ولا Undefined Behavior |
| حجم غالط (`sizeof(int)` بدل `sizeof(opt)`) | سلوك غير متوقع |

### ملخص

| المفهوم | الشرح |
|---|---|
| المشكل | "Address already in use" بعد إعادة تشغيل الـ Server |
| السبب | الـ Port مزال فـ TIME_WAIT |
| الحل | `setsockopt()` مع `SO_REUSEADDR` |
| الترتيب | بعد `socket()`، قبل `bind()` |

## 8. ()fcntl — التحكم فالـ Socket <a name="8-fcntl"></a>

### التعريف (Definition)

`fcntl()` (File Control) هي system call كتخليك **تتحكم فسلوك الـ File Descriptor**. فحالتنا، غادي نستعملوها باش نخليو الـ Socket **Non-blocking**.

### الـ Blocking vs Non-blocking

#### Blocking (الوضع الافتراضي)

ملي Socket كيكون **Blocking** (وهادا هو الوضع الافتراضي)، أي عملية عليه كتبلوكا البرنامج ديالك حتى تكمل:

```
┌─────────────────────────────────────────────┐
│            Blocking Socket                   │
├─────────────────────────────────────────────┤
│                                             │
│  accept()                                   │
│     │                                       │
│     │  كيتسنى... كيتسنى... كيتسنى...       │
│     │  (البرنامج كامل واقف)                │
│     │  ما يقدر يدير والو آخر               │
│     │                                       │
│     ▼                                       │
│  Client وصل → كمل                          │
│                                             │
│  recv()                                     │
│     │                                       │
│     │  كيتسنى... كيتسنى... كيتسنى...       │
│     │  (البرنامج كامل واقف)                │
│     │                                       │
│     ▼                                       │
│  بيانات وصلات → كمل                        │
│                                             │
└─────────────────────────────────────────────┘
```

المشكل: ملي البرنامج كيتسنى client واحد، ما يقدرش يخدم الـ Clients الآخرين.

#### Non-blocking

ملي Socket كيكون **Non-blocking**, العمليات ما كيتسنوش أبداً:

```
┌─────────────────────────────────────────────┐
│          Non-blocking Socket                 │
├─────────────────────────────────────────────┤
│                                             │
│  accept()                                   │
│     │                                       │
│     ├── كاين Client؟ → رجّعو              │
│     │                                       │
│     └── ما كاين والو؟ → رجّع -1            │
│         مع errno = EAGAIN                   │
│         (كمل خدمتك ورجع بعدا)              │
│                                             │
│  recv()                                     │
│     │                                       │
│     ├── كاينة Data؟ → رجّعها              │
│     │                                       │
│     └── ما كاينة والو؟ → رجّع -1           │
│         مع errno = EAGAIN                   │
│         (كمل خدمتك ورجع بعدا)              │
│                                             │
└─────────────────────────────────────────────┘
```

### تشبيه واقعي

**Blocking:** بحال ملي كتتصل بشي خدمة وكتتسنى على الخط. ما تقدر دير والو آخر حتى يردو عليك.

**Non-blocking:** بحال ملي كتبعث رسالة WhatsApp. كتبعثها وكترجع لخدمتك. ملي يجاوبوك، غادي تشوف الـ Notification.

### علاش ft_irc **خاصو** يستعمل Non-blocking Sockets؟

الـ 42 Subject كيقول بصراحة:

> **"All I/O operations must be non-blocking."**

ولكن حتى بلا هاد الشرط، Non-blocking ضروري حيت:

1. **بزاف ديال الـ Clients:** إيلا كان عندك 10 Clients وواحد بطيء، ما تقدرش توقف الـ Server كامل كتتسنى واحد
2. **`poll()` كيحتاجو:** الـ `poll()` (اللي غادي نستعملوه فالـ Phase الجاية) كيخدم مع Non-blocking Sockets
3. **Single-threaded Server:** حنا ما عندناش Threads — عندنا Process واحد خاصو يخدم كلشي

```
مع Blocking:                    مع Non-blocking + poll():
──────────────                  ──────────────────────────

Client 1 → recv()               poll() → شكون عندو Data؟
   ↓                               │
كتتسنى 5 ثواني...                ├── Client 1 → recv()
   ↓                               ├── Client 2 → recv()
Client 2 خاصو يتسنى!             └── Client 3 → recv()
   ↓                               │
Client 3 خاصو يتسنى!             الكل خدام فنفس الوقت!
```

### علاش `poll()` كيعتمد على Non-blocking

`poll()` كيقول ليك: "هاد الـ FDs عندهم بيانات جاهزة". ولكن:
- إيلا كان الـ Socket **Blocking** وعيطتي لـ `recv()`، والبيانات ما كاينةش بزاف، البرنامج غادي يتبلوكا
- مع **Non-blocking**, `recv()` كترجع فوراً — يا بالبيانات ولا بـ `EAGAIN`

يعني `poll()` بلا Non-blocking Sockets ما كيخدمش مزيان.

### الـ Prototype ديال `fcntl()`

```c
int fcntl(int fd, int cmd, ... /* arg */);
```

باش نخليو الـ Socket Non-blocking:
```c
fcntl(fd, F_SETFL, O_NONBLOCK);
```

| Parameter | القيمة | المعنى |
|---|---|---|
| `fd` | الـ FD ديال الـ Socket | شنو الـ FD اللي بغينا نعدلو عليه |
| `F_SETFL` | Set File Flags | بغينا نبدلو الـ Flags |
| `O_NONBLOCK` | Non-blocking Flag | خلي الـ Socket Non-blocking |

### أمثلة عملية

#### مثال 1: الفرق فالسلوك

```
Blocking accept():
──────────────────
البرنامج كيعيط لـ accept()
   ↓
ما كاين حتى Client
   ↓
كيتسنى... 1 ثانية... 2 ثواني... 5 ثواني...
   ↓
Client وصل → accept() رجعات الـ FD
   ↓
كمل

Non-blocking accept():
──────────────────────
البرنامج كيعيط لـ accept()
   ↓
ما كاين حتى Client
   ↓
accept() رجعات -1 مع EAGAIN (فوراً!)
   ↓
البرنامج كمل خدمة وحدة أخرى
   ↓
رجع عيط لـ accept() مرة أخرى
```

#### مثال 2: Server مع بزاف ديال Clients

```
Non-blocking Server مع poll():
──────────────────────────────

┌─ poll() ←──────────────────────────────────┐
│    │                                        │
│    ├── Listening Socket جاهز؟               │
│    │      └── نعم → accept() → Client جديد │
│    │                                        │
│    ├── Client 1 عندو Data؟                 │
│    │      └── نعم → recv() → عالج          │
│    │                                        │
│    ├── Client 2 عندو Data؟                 │
│    │      └── لا → تجاوزو                  │
│    │                                        │
│    └── Client 3 عندو Data؟                 │
│           └── نعم → recv() → عالج          │
│                                             │
└─────────────── عاود الدورة ─────────────────┘
```

### ملخص

| المفهوم | الشرح |
|---|---|
| Blocking | البرنامج كيوقف حتى تكمل العملية |
| Non-blocking | البرنامج ما كيوقفش — كيرجع فوراً |
| `fcntl()` | System call كتبدل Flags ديال الـ FD |
| `O_NONBLOCK` | الـ Flag اللي كيخلي الـ Socket Non-blocking |
| `EAGAIN` | Error code كيعني "ما كاين والو دابا، رجع بعدا" |
| علاش Non-blocking | 42 Subject كيطلبو + `poll()` كيحتاجو |

## 9. ()bind — ربط الـ Socket بالعنوان <a name="9-bind"></a>

### التعريف (Definition)

`bind()` كتربط الـ Socket بـ **عنوان محدد** (IP Address + Port). بدون `bind()`, الـ Socket عندو رقم (FD) ولكن ما عندوش عنوان — يعني ما حدش يقدر يلقاه فالشبكة.

### تشبيه واقعي

```
socket() = شريتي تيليفون
bind()   = سجلتي رقم فيه (IP + Port)
```

بلا رقم، ما حدش يقدر يعيط ليك. نفس الحاجة: بلا `bind()`, ما حدش يقدر يتصل بالـ Server ديالك.

### الـ Port (الباب)

**Port** هو رقم بين **0 و 65535** كيمثل **خدمة معينة** على الجهاز.

تخيل الـ IP Address بحال عنوان العمارة. الـ Port بحال رقم الشقة:

```
IP Address    = عنوان العمارة (192.168.1.1)
Port          = رقم الشقة (6667)
العنوان الكامل = 192.168.1.1:6667
```

بعض الـ Ports المعروفين:

| Port | الخدمة |
|---|---|
| 80 | HTTP (المواقع) |
| 443 | HTTPS (المواقع المشفرة) |
| 22 | SSH |
| 6667 | IRC (الافتراضي) |

> **ملاحظة:** الـ Ports من 0 لـ 1023 محجوزين (**Well-Known Ports**) — خاصك تكون `root` باش تستعملهم. الـ Ports من 1024 لـ 65535 متاحين للبرامج العادية.

### الـ IP Address

الـ IP Address كيحدد **الجهاز** فالشبكة. فـ ft_irc عندنا خيارات:

| القيمة | المعنى |
|---|---|
| `INADDR_ANY` (0.0.0.0) | اسمع على **كل** الـ Interfaces — هادا اللي كنستعملو |
| `127.0.0.1` | اسمع غير على localhost |
| `192.168.1.x` | اسمع غير على Interface معين |

`INADDR_ANY` هو الأحسن فالتطوير حيت كيخليك تتصل من أي مكان.

### الربط (Binding)

`bind()` كتقول للـ Kernel: **"هاد الـ Socket (FD 3) خاصو يستقبل كل الاتصالات اللي جاية للعنوان 0.0.0.0 على الـ Port 6667"**.

```
قبل bind():
─────────────
Socket (FD 3)  →  ما عندو حتى عنوان

بعد bind():
─────────────
Socket (FD 3)  →  0.0.0.0:6667
```

### الملكية (Ownership)

ملي كتعمل `bind()` على Port معين، **أنت المالك ديال هاد الـ Port**. ما يقدرش برنامج آخر يستعمل نفس الـ Port فنفس الوقت.

### الربط الحصري (Exclusive Binding)

**غير Process واحد** يقدر يعمل `bind()` على Port معين فنفس الوقت:

```
Process A:  bind(fd, 0.0.0.0:6667)  →  ✓ نجاح
Process B:  bind(fd, 0.0.0.0:6667)  →  ✗ Error: Address already in use!
```

هادشي منطقي: إيلا جاء اتصال على Port 6667، الـ OS خاصو يعرف **شكون** اللي غادي يستقبلو. إيلا كانو جوج برامج على نفس الـ Port، غادي يكون الـ Chaos.

### علاش غير Process واحد يقدر يملك Port؟

```
┌──────────────────────────────────────────────┐
│           ملكية الـ Port                       │
├──────────────────────────────────────────────┤
│                                              │
│    Port 6667                                 │
│    ┌──────────────────┐                      │
│    │     المالك:       │                      │
│    │     ft_irc        │  ← Process واحد     │
│    │     (PID: 1234)   │                      │
│    └──────────────────┘                      │
│                                              │
│    Process آخر بغا نفس الـ Port:             │
│    bind(fd, 0.0.0.0:6667) → ✗ مرفوض!       │
│                                              │
│    السبب: الـ Kernel ما يقدرش يقرر شكون     │
│    غادي يستقبل الـ Packets اللي جاية        │
│    على Port 6667.                           │
│                                              │
└──────────────────────────────────────────────┘
```

### الـ Prototype

```c
int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
```

| Parameter | المعنى |
|---|---|
| `sockfd` | الـ FD ديال الـ Socket |
| `addr` | Pointer للعنوان (struct sockaddr_in) |
| `addrlen` | حجم الـ Structure |

الـ `struct sockaddr_in` كتحتوي على:

```
struct sockaddr_in {
    sa_family_t    sin_family;   // AF_INET
    in_port_t      sin_port;     // الـ Port (بـ Network Byte Order)
    struct in_addr sin_addr;     // الـ IP Address
};
```

> **Network Byte Order:** الشبكة كتستعمل **Big-Endian** (الـ byte الكبير أولاً). الجهاز ديالك ممكن يكون **Little-Endian**. `htons()` كتحول من الـ Host byte order للـ Network byte order.

### أمثلة على الأخطاء

| الخطأ | السبب |
|---|---|
| `EADDRINUSE` | الـ Port محجوز — استعمل `setsockopt(SO_REUSEADDR)` |
| `EACCES` | كتحاول تستعمل Port < 1024 بلا `root` |
| `EBADF` | الـ FD اللي عطيتي ماشي صالح |
| `EINVAL` | الـ Socket مربوط من قبل (`bind()` تعملات مرتين) |

### ملخص

| المفهوم | الشرح |
|---|---|
| Port | رقم كيحدد الخدمة (0-65535) |
| IP | عنوان الجهاز فالشبكة |
| `bind()` | كتربط Socket بعنوان (IP + Port) |
| Exclusive | غير Process واحد يقدر يملك Port واحد |
| `INADDR_ANY` | اسمع على كل الـ Interfaces |
| `htons()` | حول الـ Port لـ Network Byte Order |

## 10. ()listen — بداية الإنصات <a name="10-listen"></a>

### التعريف (Definition)

`listen()` كتحول الـ Socket من **حالة عادية** لـ **حالة الإنصات** (Listening State). بعد `listen()`, الـ Socket كيكون مستعد يستقبل الاتصالات.

### تشبيه واقعي

```
socket()     = بنيت أوطيل
bind()       = عطيتيه عنوان
listen()     = فتحت الاستقبال (Reception) وحطيت الموظف
```

قبل `listen()`, الأوطيل موجود وعندو عنوان، ولكن **ما كاين حتى واحد فالاستقبال** — ما حدش يقدر يدخل.

بعد `listen()`, **الاستقبال خدام** — الناس يقدرو يدقو وكيتسناو حتى تقبلهم.

### حالة الإنصات (Listening State)

```
قبل listen():
──────────────
Socket State: CREATED (ولا BOUND)
→ ما يقدرش يستقبل اتصالات

بعد listen():
──────────────
Socket State: LISTENING
→ كيتسنى الاتصالات الجديدة
→ الـ Kernel كيخلق Backlog Queue
```

ملي `listen()` كتنجح، الـ Kernel كيبدل حالة الـ Socket لـ `LISTEN` وكيخلق **Backlog Queue**.

### الـ Backlog Queue (طابور الانتظار)

الـ **Backlog** هو **طابور الانتظار** ديال الاتصالات اللي وصلات ولكن مزال ما تقبلات.

```
┌──────────────────────────────────────────────┐
│         الـ Listening Socket                  │
│                                              │
│   ┌────────────────────────────────┐         │
│   │      Backlog Queue              │         │
│   │  (طابور الانتظار)              │         │
│   │                                │         │
│   │  ┌─────┐ ┌─────┐ ┌─────┐      │         │
│   │  │ C1  │ │ C2  │ │ C3  │      │  ← جاو  │
│   │  └─────┘ └─────┘ └─────┘      │         │
│   │                                │         │
│   │  كيتسناو accept()...          │         │
│   │                                │         │
│   └────────────────────────────────┘         │
│                                              │
│   accept() → كياخذ واحد من الطابور          │
│   وكيخلق Socket جديد خاص بيه               │
│                                              │
└──────────────────────────────────────────────┘
```

ملي Client كيتصل بالـ Server:
1. الـ TCP Three-Way Handshake كيكمل
2. الاتصال كيدخل **الـ Backlog Queue**
3. كيتسنى حتى البرنامج يعيط لـ `accept()`
4. `accept()` كياخذ الاتصال من الطابور وكيخلق Socket جديد

### الاتصالات المعلقة (Pending Connections)

الـ `backlog` parameter فـ `listen()` كيحدد **الحد الأقصى ديال الاتصالات المعلقة**:

```c
int listen(int sockfd, int backlog);
```

| Parameter | المعنى |
|---|---|
| `sockfd` | الـ FD ديال الـ Socket |
| `backlog` | الحد الأقصى ديال الاتصالات اللي تقدر تتسنى فالطابور |

إيلا الطابور فايض (وصل للـ `backlog`)، الاتصالات الجديدة **كيترفضو** (ولا كيتجاهلو حسب الـ OS).

```
backlog = 5

┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐
│ C1  │ │ C2  │ │ C3  │ │ C4  │ │ C5  │  ← 5 فالطابور (فايض)
└─────┘ └─────┘ └─────┘ └─────┘ └─────┘

Client 6 كيحاول يتصل → مرفوض! (ولا كيتسنى)
```

> **نصيحة:** `SOMAXCONN` هي القيمة الأقصى اللي الـ OS كيسمح بيها. تقدر تستعملها بدل رقم ثابت. ولكن فـ ft_irc، قيمة بحال `10` ولا `128` كافية.

### الفرق بين `bind()` و `listen()`

| `bind()` | `listen()` |
|---|---|
| كتعطي الـ Socket **عنوان** | كتحول الـ Socket لحالة **الإنصات** |
| كتربط IP + Port | كتخلق الـ Backlog Queue |
| ما كيقدرش يستقبل اتصالات بعد | كيقدر يستقبل اتصالات |
| بحال تسجيل رقم التيليفون | بحال تشعيل التيليفون |

### شنو كيوقع داخل الـ Kernel

```
┌──────────────────────────────────────────────┐
│    listen(fd, backlog)                        │
│        │                                     │
│        ▼                                     │
│    الـ Kernel كيدير:                          │
│                                              │
│    1. كيبدل حالة الـ Socket                  │
│       BOUND → LISTENING                      │
│                                              │
│    2. كيخلق Backlog Queue                    │
│       ┌────────────────────────┐             │
│       │ SYN Queue (نصف مكملين)│             │
│       │ Accept Queue (مكملين) │             │
│       └────────────────────────┘             │
│                                              │
│    3. كيبدا يستقبل SYN Packets               │
│       من الـ Clients                         │
│                                              │
│    4. كيدير TCP Three-Way Handshake           │
│       أوتوماتيكياً                           │
│                                              │
│    5. كيضيف الاتصالات المكملة               │
│       للـ Accept Queue                       │
│                                              │
└──────────────────────────────────────────────┘
```

> **ملاحظة مهمة:** الـ Kernel كيدير الـ TCP Handshake **أوتوماتيكياً** بلا ما البرنامج ديالك يدير أي شيء. البرنامج غير كيعيط لـ `accept()` باش ياخذ الاتصال اللي مكمل.

### مثال على السلوك

```
الحالة 1: الطابور فارغ
──────────────────────
listen() نجحات
ما كاين حتى Client
الـ Server كيتسنى... (بـ poll())

الحالة 2: Client جديد
──────────────────────
Client كيبعث SYN
Kernel كيرد SYN-ACK
Client كيبعث ACK
الاتصال كمل → كيدخل الـ Accept Queue
البرنامج كيعيط لـ accept() → كياخذو

الحالة 3: الطابور فايض
──────────────────────
5 Clients كيتسناو فالطابور (backlog = 5)
Client 6 كيحاول يتصل
الـ Kernel كيتجاهل الـ SYN ديالو
Client 6 كيعاود يحاول... وممكن ينجح إيلا تحرر مكان
```

### ملخص

| المفهوم | الشرح |
|---|---|
| `listen()` | كتحول الـ Socket لحالة الإنصات |
| Listening State | الـ Socket جاهز يستقبل الاتصالات |
| Backlog Queue | طابور الاتصالات اللي كيتسناو `accept()` |
| `backlog` parameter | الحد الأقصى ديال الطابور |
| بعد `listen()` | الـ Server جاهز — كيتسنى الـ Clients |

## 11. دورة حياة الـ Socket الكاملة <a name="11-دورة-حياة-الـ-socket-الكاملة"></a>

### الرسم التوضيحي الكامل

دابا غادي نجمعو كلشي فرسم واحد كبير اللي كيوري المسار الكامل ديال الـ Socket من البداية حتى ما يكون جاهز:

```
╔══════════════════════════════════════════════════════════════════════╗
║                    دورة حياة الـ Socket الكاملة                      ║
║                    Socket Lifecycle                                  ║
╠══════════════════════════════════════════════════════════════════════╣
║                                                                     ║
║    ┌─────────────────────────────────────────────────┐              ║
║    │  1. socket(AF_INET, SOCK_STREAM, 0)             │              ║
║    │     → خلق الـ Socket                            │              ║
║    │     → كيرجع FD (مثلاً 3)                       │              ║
║    │     → الـ Socket مخلوق ولكن بلا عنوان          │              ║
║    └────────────────────┬────────────────────────────┘              ║
║                         │                                           ║
║                         ▼                                           ║
║    ┌─────────────────────────────────────────────────┐              ║
║    │  2. setsockopt(fd, SOL_SOCKET, SO_REUSEADDR, &) │              ║
║    │     → فعّل إعادة استعمال العنوان                │              ║
║    │     → باش نتفاداو "Address already in use"      │              ║
║    │     → الـ Socket مزال بلا عنوان                 │              ║
║    └────────────────────┬────────────────────────────┘              ║
║                         │                                           ║
║                         ▼                                           ║
║    ┌─────────────────────────────────────────────────┐              ║
║    │  3. fcntl(fd, F_SETFL, O_NONBLOCK)              │              ║
║    │     → خلّي الـ Socket Non-blocking               │              ║
║    │     → باش ما يتبلوكاش البرنامج                  │              ║
║    │     → ضروري لـ poll()                           │              ║
║    └────────────────────┬────────────────────────────┘              ║
║                         │                                           ║
║                         ▼                                           ║
║    ┌─────────────────────────────────────────────────┐              ║
║    │  4. bind(fd, addr, sizeof(addr))                │              ║
║    │     → ربط الـ Socket بـ 0.0.0.0:6667            │              ║
║    │     → دابا عندو عنوان                          │              ║
║    │     → الـ Port 6667 مملوك من الـ Server         │              ║
║    └────────────────────┬────────────────────────────┘              ║
║                         │                                           ║
║                         ▼                                           ║
║    ┌─────────────────────────────────────────────────┐              ║
║    │  5. listen(fd, SOMAXCONN)                       │              ║
║    │     → الـ Socket ولا Listening                  │              ║
║    │     → Backlog Queue تخلقات                      │              ║
║    │     → الـ Kernel كيقبل TCP Handshakes           │              ║
║    └────────────────────┬────────────────────────────┘              ║
║                         │                                           ║
║                         ▼                                           ║
║    ┌─────────────────────────────────────────────────┐              ║
║    │  ✓ الـ Server جاهز!                            │              ║
║    │    كيتسنى الاتصالات...                         │              ║
║    │                                                 │              ║
║    │    (Phase 2 كتوقف هنا)                         │              ║
║    │                                                 │              ║
║    │    الجاي: accept() + poll() (Phase 3)          │              ║
║    └─────────────────────────────────────────────────┘              ║
║                                                                     ║
╚══════════════════════════════════════════════════════════════════════╝
```

### شرح كل انتقال

#### من `socket()` لـ `setsockopt()`

بعد `socket()`, عندنا Socket جديد بـ FD. ولكن قبل ما نربطوه بعنوان، خاصنا **نعدلو الإعدادات ديالو**. `setsockopt()` خاصها تجي قبل `bind()` حيت `SO_REUSEADDR` كيأثر على سلوك `bind()`.

#### من `setsockopt()` لـ `fcntl()`

بعد الإعدادات، خاصنا نخليو الـ Socket **Non-blocking** باش يكون جاهز لـ `poll()`. هاد الخطوة يقدر تكون قبل ولا بعد `bind()`، ولكن منطقياً كنحطوها هنا.

#### من `fcntl()` لـ `bind()`

دابا الـ Socket عندو الإعدادات المناسبة. خاصنا **نعطيوه عنوان**. `bind()` كتربطو بالـ IP والـ Port اللي بغينا.

#### من `bind()` لـ `listen()`

الـ Socket عندو عنوان دابا. ولكن مزال ما كيقبلش الاتصالات. `listen()` كتحولو **لحالة الإنصات** وكتخلق الـ Backlog Queue.

#### بعد `listen()`

الـ Server **جاهز**. كيتسنى الاتصالات. الخطوة الجاية هي `accept()` و `poll()` — ولكن هادوك ماشي ديال هاد الـ Phase.

### جدول الانتقالات

| الحالة | الخطوة | النتيجة |
|---|---|---|
| ما كاين والو | `socket()` | Socket موجود، بلا عنوان، بلا إنصات |
| Socket موجود | `setsockopt()` | Socket بإعدادات مناسبة |
| Socket معدّل | `fcntl()` | Socket Non-blocking |
| Socket Non-blocking | `bind()` | Socket مربوط بعنوان (IP:Port) |
| Socket مربوط | `listen()` | Socket فحالة الإنصات — **جاهز!** |

## 14. التكامل (Integration) <a name="14-التكامل"></a>

### شنو كيعطي Ayoub لـ Ismail؟

بعد ما يكمل Phase 2, Ayoub كيعطي لـ Ismail:

```
╔══════════════════════════════════════════════╗
║        اللي كيعطيه Ayoub لـ Ismail           ║
╠══════════════════════════════════════════════╣
║                                              ║
║  1. Listening Socket (FD جاهز)              ║
║     → Socket مفتوح، مربوط، كيتسنى          ║
║                                              ║
║  2. Server Initialization                    ║
║     → init() كيدير كلشي:                    ║
║        socket() → setsockopt() → fcntl()    ║
║        → bind() → listen()                  ║
║                                              ║
║  3. Socket Configuration                     ║
║     → Non-blocking                           ║
║     → SO_REUSEADDR                           ║
║     → مربوط بالـ Port المناسب               ║
║                                              ║
║  4. Server Ready to accept()                 ║
║     → الـ Socket فحالة LISTENING             ║
║     → الـ Backlog Queue خدامة               ║
║     → أي Client يقدر يتصل                  ║
║                                              ║
╚══════════════════════════════════════════════╝
```

### شنو غادي ينيمبلومونطي Ismail بعد هادشي؟

```
Ismail فالـ Phase الجاية:
═════════════════════════

1. كيضيف الـ Listening FD لـ poll()
2. كيبدا الـ Event Loop
3. ملي poll() كيقول "كاين Client جديد":
   → كيعيط لـ accept()
   → كياخذ الـ Client FD الجديد
   → كيخلق Client Object
   → كيضيف الـ Client FD لـ poll()

4. ملي poll() كيقول "Client عندو Data":
   → كيعيط لـ recv()
   → كيمرر البيانات لـ Souhail (BufferManager)
   → كيعالج الرسائل

يعني:
    init()     ← Ayoub (Phase 2) ✓
       ↓
    run()      ← Ismail + Ayoub (Phase 3)
       ↓
    poll()     ← Ayoub (Phase 3)
       ↓
    accept()   ← Ayoub (Phase 3)
       ↓
    Client     ← Ismail (Phase 3)
```

## 16. التعامل مع الأخطاء (Error Handling) <a name="16-التعامل-مع-الأخطاء"></a>

### القاعدة الذهبية

> **ما تتجاهل أبداً القيمة اللي كترجع من System Call.**

كل System Call يقدر يفشل. إيلا تجاهلتي الفشل، البرنامج غادي يكمل بقيم غالطة وغادي يكراشي فمكان آخر — وما غاديش تعرف علاش.

### أخطاء `socket()`

| الـ errno | المعنى | شنو تدير |
|---|---|---|
| `EMFILE` | Process وصل للحد الأقصى ديال الـ FDs | سد الـ FDs اللي ما خاصينش |
| `ENFILE` | النظام كامل وصل للحد | ما فيدكش — النظام مشبع |
| `ENOMEM` | ما بقاتش ذاكرة | سد البرنامج |
| `EACCES` | ما عندكش الصلاحيات | شغل كـ root ولا غيّر الإعدادات |

**كيفاش تتعامل:**
```
socket() رجعات -1?
   ↓
اطبع Error message واضح مع perror() ولا strerror(errno)
   ↓
خرج من البرنامج (ما تكملش)
```

### أخطاء `setsockopt()`

| الـ errno | المعنى |
|---|---|
| `EBADF` | الـ FD ماشي صالح |
| `ENOPROTOOPT` | الـ Option ما كاينةش |
| `EINVAL` | القيمة غالطة |

**كيفاش تتعامل:**
```
setsockopt() رجعات -1?
   ↓
اطبع Error message
   ↓
سد الـ Socket بـ close(fd)
   ↓
خرج من البرنامج
```

### أخطاء `fcntl()`

| الـ errno | المعنى |
|---|---|
| `EBADF` | الـ FD ماشي صالح |
| `EINVAL` | الـ Command ولا الـ Argument غالط |

**كيفاش تتعامل:**
```
fcntl() رجعات -1?
   ↓
اطبع Error message
   ↓
close(fd)
   ↓
خرج من البرنامج
```

### أخطاء `bind()`

| الـ errno | المعنى | الحل |
|---|---|---|
| `EADDRINUSE` | الـ Port محجوز | `setsockopt(SO_REUSEADDR)` ولا بدّل الـ Port |
| `EACCES` | Port < 1024 بلا root | استعمل Port أكبر من 1024 |
| `EBADF` | الـ FD ماشي صالح | تأكد من `socket()` |
| `EINVAL` | الـ Socket مربوط من قبل | ما تعيطش `bind()` مرتين |

**كيفاش تتعامل:**
```
bind() رجعات -1?
   ↓
اطبع Error message مع الـ Port
   ↓
close(fd)
   ↓
خرج من البرنامج
```

### أخطاء `listen()`

| الـ errno | المعنى |
|---|---|
| `EBADF` | الـ FD ماشي صالح |
| `ENOTSOCK` | الـ FD ماشي Socket |
| `EOPNOTSUPP` | نوع الـ Socket ما كيدعمش `listen()` |

**كيفاش تتعامل:**
```
listen() رجعات -1?
   ↓
اطبع Error message
   ↓
close(fd)
   ↓
خرج من البرنامج
```

### مسار Error Handling الكامل

```
socket()
  │
  ├── نجح → كمل
  └── فشل → Error + Exit

setsockopt()
  │
  ├── نجح → كمل
  └── فشل → Error + close(fd) + Exit

fcntl()
  │
  ├── نجح → كمل
  └── فشل → Error + close(fd) + Exit

bind()
  │
  ├── نجح → كمل
  └── فشل → Error + close(fd) + Exit

listen()
  │
  ├── نجح → كمل ✓
  └── فشل → Error + close(fd) + Exit
```

### علاش ما خاصكش تتجاهل القيم اللي كترجع (Return Values)

```
المشكل:
═══════
int fd = socket(...);
// ما شيكيتيش واش fd == -1
bind(fd, ...);  // ← كتعيط bind() بـ fd = -1
                //    سلوك غير معروف!
                //    ممكن Segfault
                //    ممكن يخدم غلط بلا ما تعرف

الحل:
═════
int fd = socket(...);
if (fd == -1) {
    // Error handling واضح
    // كتعرف بالضبط فين المشكل
}
```

## 17. أخطاء المبتدئين الشائعة (Common Beginner Mistakes) <a name="17-أخطاء-المبتدئين-الشائعة"></a>

### 1. ❌ استعمال Port غالط

```
الخطأ: ./ircserv 99999 pass
المشكل: الـ Port خاصو يكون بين 0 و 65535
الحل: فاليدي الـ Port قبل ما تستعملو
```

### 2. ❌ Socket كيبقى Blocking

```
الخطأ: نسيان fcntl(fd, F_SETFL, O_NONBLOCK)
المشكل: الـ Server كيتبلوكا على أول accept() ولا recv()
الحل: ديما دير fcntl() بعد socket()
```

### 3. ❌ نسيان `close()`

```
الخطأ: الـ Server كيوقف بلا ما يسد الـ Socket
المشكل: FD Leak — الـ Port يبقى محجوز
الحل: ديما close(fd) فالـ Destructor ولا ملي كيوقع Error
```

### 4. ❌ استعمال UDP بدل TCP

```
الخطأ: socket(AF_INET, SOCK_DGRAM, 0)  ← UDP!
المشكل: IRC خاصو TCP
الحل: socket(AF_INET, SOCK_STREAM, 0)  ← TCP
```

### 5. ❌ استعمال AF_INET6 بدل AF_INET

```
الخطأ: socket(AF_INET6, SOCK_STREAM, 0)
المشكل: IPv6 ما خاصكش فـ ft_irc (إلا طلبو Subject)
الحل: socket(AF_INET, SOCK_STREAM, 0)
```

### 6. ❌ Protocol غالط

```
الخطأ: socket(AF_INET, SOCK_STREAM, 17)  ← 17 = UDP!
المشكل: كيخلط Protocols
الحل: socket(AF_INET, SOCK_STREAM, 0)  ← خلي الـ OS يختار
```

### 7. ❌ Backlog = 0

```
الخطأ: listen(fd, 0)
المشكل: ما كاين حتى مكان للاتصالات المعلقة
الحل: listen(fd, SOMAXCONN) ولا listen(fd, 128)
```

### 8. ❌ Backlog كبير بزاف

```
الخطأ: listen(fd, 1000000)
المشكل: الـ OS كيتجاهل الأرقام الكبيرة ديما
الحل: listen(fd, SOMAXCONN) ← الحد الأقصى ديال النظام
```

### 9. ❌ نسيان `setsockopt()` — "Address already in use"

```
الخطأ: بعد Ctrl+C، ما تقدرش تعاود تشغل الـ Server
المشكل: الـ Port فـ TIME_WAIT
الحل: setsockopt(fd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt))
```

### 10. ❌ `setsockopt()` بعد `bind()`

```
الخطأ: bind() أولاً ثم setsockopt()
المشكل: SO_REUSEADDR ما كيأثرش بعد bind()
الحل: setsockopt() قبل bind()
```

### 11. ❌ نسيان `htons()` فالـ Port

```
الخطأ: addr.sin_port = 6667
المشكل: الـ Byte Order غالط — الـ Port ما كيبانش صحيح
الحل: addr.sin_port = htons(6667)
```

### 12. ❌ نسيان `memset()` / `bzero()` ديال الـ `sockaddr_in`

```
الخطأ: struct sockaddr_in addr; بلا تصفير
المشكل: القيم القديمة فالذاكرة كيسببو سلوك غريب
الحل: memset(&addr, 0, sizeof(addr))
```

### 13. ❌ التحقق من الأخطاء بشكل غالط

```
الخطأ: if (socket(...) == 0)  ← غالط!
المشكل: socket() كترجع -1 فحالة الفشل، ماشي 0
الحل: if (socket(...) == -1) ولا if (socket(...) < 0)
```

### 14. ❌ استعمال `errno` بلا ما تشيكي أولاً

```
الخطأ: كتشوف errno بلا ما تتأكد بلي الـ function فشلات
المشكل: errno كتتبدل مع كل system call
الحل: شيكي return value أولاً، ثم شوف errno
```

### 15. ❌ `bind()` مرتين

```
الخطأ: bind(fd, ...) مرتين
المشكل: EINVAL — الـ Socket مربوط من قبل
الحل: bind() مرة وحدة فقط
```

### 16. ❌ `listen()` قبل `bind()`

```
الخطأ: listen() بلا bind() قبلها
المشكل: الـ Socket ما عندوش عنوان — أين غادي يتسنى؟
الحل: bind() أولاً، listen() بعدها
```

### 17. ❌ ما كيتعاملش مع SIGPIPE

```
الخطأ: ما عملش signal(SIGPIPE, SIG_IGN)
المشكل: إيلا Client خرج وبعثتي ليه data، الـ Server كيموت
الحل: signal(SIGPIPE, SIG_IGN) ولا MSG_NOSIGNAL فـ send()
```

### 18. ❌ Hard-coding الـ Port

```
الخطأ: addr.sin_port = htons(6667) ← ديما 6667
المشكل: الـ Subject كيقول الـ Port كيجي كـ Argument
الحل: استعمل argv[1]
```

### 19. ❌ ما كيسدش الـ Socket ملي كيوقع Error

```
الخطأ: bind() فشل → خرج بلا close()
المشكل: FD Leak
الحل: ديما close(fd) قبل ما تخرج بالـ Error
```

### 20. ❌ كيستعمل `select()` بدل `poll()`

```
الخطأ: استعمال select() فالـ Event Loop
المشكل: الـ 42 Subject كيقول "poll() (or equivalent)"
الحل: استعمل poll() ولا epoll() — ماشي select()
```

### 21. ❌ كيدير `accept()` فالـ init()

```
الخطأ: عيطت لـ accept() مباشرة بعد listen()
المشكل: accept() ماشي ديال Phase 2 — خاصها تكون فالـ Event Loop
الحل: خلي accept() للـ run() (Phase 3)
```

### 22. ❌ ما كيفهمش الفرق بين Listening Socket و Client Socket

```
الخطأ: كيحاول يقرا من الـ Listening Socket بـ recv()
المشكل: الـ Listening Socket ما كيبعثش/كيستقبلش Data
الحل: الـ Listening Socket غير لـ accept()
      الـ Client Socket هو اللي لـ recv()/send()
```

### 23. ❌ كينسى يعمل Non-blocking للـ Client Sockets الجداد

```
الخطأ: accept() كيرجع Client FD → ما كيديرش fcntl()
المشكل: الـ Client Socket Blocking — كيبلوكا poll()
الحل: كل Socket جديد من accept() خاصو fcntl(O_NONBLOCK)
```

```
  socket() ──── فشل? ──── نعم ──→ perror() → exit(1)
     │
     │ لا (نجح)
     ▼
  setsockopt() ── فشل? ── نعم ──→ perror() → close(fd) → exit(1)
     │
     │ لا
     ▼
  fcntl() ────── فشل? ── نعم ──→ perror() → close(fd) → exit(1)
     │
     │ لا
     ▼
  bind() ─────── فشل? ── نعم ──→ perror() → close(fd) → exit(1)
     │
     │ لا
     ▼
  listen() ───── فشل? ── نعم ──→ perror() → close(fd) → exit(1)
     │
     │ لا
     ▼
  ✓ Server جاهز!
```

### الرسم 13: TIME_WAIT Problem

```
  الحالة 1: بلا SO_REUSEADDR
  ───────────────────────────

  Server يشتغل ← Port 6667 محجوز
       │
  Ctrl+C (Server يوقف)
       │
  Port 6667 فـ TIME_WAIT (60 ثانية)
       │
  Server يشتغل مرة أخرى
       │
  bind() ← ✗ EADDRINUSE!
       │
  كيتسنى 60 ثانية...
       │
  bind() ← ✓ نجاح (بعد الانتظار)


  الحالة 2: مع SO_REUSEADDR
  ──────────────────────────

  Server يشتغل ← Port 6667 محجوز
       │
  Ctrl+C (Server يوقف)
       │
  Port 6667 فـ TIME_WAIT
       │
  Server يشتغل مرة أخرى
       │
  setsockopt(SO_REUSEADDR) ✓
       │
  bind() ← ✓ نجاح فوراً!
```

### الرسم 14: Blocking vs Non-blocking Comparison

```
  Blocking Server:                Non-blocking Server + poll():
  ═════════════════               ═════════════════════════════

  accept()                        poll(fds, nfds, timeout)
     │                               │
     │ كيتسنى...                    ├── FD 3 جاهز? → accept()
     │ كيتسنى...                    ├── FD 4 جاهز? → recv()
     │ كيتسنى...                    ├── FD 5 جاهز? → recv()
     │                               └── عاود الدورة
     ▼
  Client وصل                       كلشي فنفس الوقت!
     │                               ما كيتسنى حتى واحد
  recv(client_fd)
     │
     │ كيتسنى Data...
     │ كيتسنى...
     │
     ▼
  Data وصلات

  Client 2 و 3 مبلوكين!
  ما يقدروش يتصلو حتى يكمل Client 1
```

## 19. تشبيهات من الحياة الواقعية (Real-life Analogies) <a name="19-تشبيهات-من-الحياة-الواقعية"></a>

### 🏨 تشبيه الأوطيل (Hotel)

الـ IRC Server بحال **أوطيل كبير**:

| المفهوم التقني | التشبيه |
|---|---|
| `socket()` | بناء الأوطيل |
| `bind()` | تسجيل العنوان ديال الأوطيل (الشارع + الرقم) |
| `listen()` | فتح الاستقبال (Reception) وحط الموظف |
| `accept()` | الموظف كيقبل ضيف جديد وكيعطيه مفتاح الغرفة |
| Listening Socket | الاستقبال — ديما مفتوح، ديما كيتسنى |
| Client Socket | الغرفة — خاصة بالضيف |
| `close()` | الضيف كيخرج والغرفة كتتنضف |
| Port | رقم الأوطيل فالشارع |
| Backlog | عدد الكراسي فصالة الانتظار |
| `poll()` | الموظف اللي كيراقب كلشي: الباب + الغرف |

**السيناريو الكامل:**
1. كتبني الأوطيل (`socket()`)
2. كتسجلو فالبلدية بعنوان رسمي (`bind()`)
3. كتحل الاستقبال وكتحط كراسي الانتظار (`listen()`)
4. الضيوف كيوصلو وكيتسناو (`Backlog Queue`)
5. الموظف كيقبل كل ضيف وكيعطيه غرفتو (`accept()`)
6. الضيف كيتواصل مع الأوطيل من غرفتو (`recv()`/`send()`)
7. الضيف كيخرج (`close()`)

### 📞 تشبيه التيليفون (Telephone)

الـ IRC Server بحال **مركز الاتصالات** (Call Center):

| المفهوم التقني | التشبيه |
|---|---|
| `socket()` | شراء خط تيليفوني |
| `bind()` | تسجيل رقم التيليفون |

| `recv()` | الإنصات لللي كيقول لك المتصل |
| `send()` | الرد على المتصل |
| `close()` | قطع المكالمة |
| Port | رقم التيليفون |
| Backlog | عدد المكالمات اللي يقدرو يتسناو على الخط |

### 📮 تشبيه البوسطة (Post Office)

الـ TCP بحال **بوسطة موثوقة** (Registered Mail):

| المفهوم التقني | التشبيه |
|---|---|
| TCP | البوسطة المضمونة — كل برية كتوصل |
| UDP | البوسطة العادية — ممكن تضيع |

| ACK | إشعار الاستلام |

## 21. الخلاصة (Key Takeaways) <a name="21-الخلاصة"></a>

### ملخص Phase 2 بالكامل

هاد الـ Phase كانت على **الأساس الشبكي** ديال الـ IRC Server. هادو هما النقاط الرئيسية:

### 1. الـ Socket هو الأساس
- بلا Socket، ما كاين حتى اتصال
- الـ Socket هو الجسر بين البرنامج والشبكة
- الـ Kernel هو اللي كيدير الخدمة الصعيبة — أنت غير كتستعمل الـ FD

### 2. TCP كيضمن الموثوقية
- كل رسالة كتوصل
- كل رسالة كتوصل بالترتيب
- إيلا ضاعت كتتبعث مرة أخرى
- هادشي ضروري لـ IRC

### 3. الـ File Descriptor هو المفتاح
- كل حاجة فـ Linux هي ملف
- الـ Socket كيتمثل برقم (FD)
- خاصك تسدو بـ `close()` ملي تسالي

### 4. خمسة System Calls — بالترتيب
```
socket() → setsockopt() → fcntl() → bind() → listen()
```
كل واحد عندو دور محدد. الترتيب مهم.

### 5. Non-blocking ضروري
- الـ 42 Subject كيطلبو
- `poll()` كيحتاجو
- بلاه الـ Server ما يقدرش يخدم بزاف ديال الـ Clients

### 6. Error Handling ماشي اختياري
- كل System Call يقدر يفشل
- ما تتجاهل أبداً الـ Return Value
- سد الـ FD قبل ما تخرج بالـ Error

### 7. Phase 2 كتوقف عند `listen()`
- ما كنديروش `accept()`
- ما كنديروش `poll()`
- ما كنديروش `recv()` ولا `send()`
- هادوك ديال Phase الجاية

### جدول ملخص

| System Call | الدور | النتيجة |
|---|---|---|
| `socket()` | خلق الـ Socket | FD جديد |
| `setsockopt()` | إعداد الـ Socket | SO_REUSEADDR مفعل |
| `fcntl()` | Non-blocking | ما كيتبلوكاش |
| `bind()` | عنوان (IP:Port) | Port محجوز |
| `listen()` | بداية الإنصات | Server جاهز |
