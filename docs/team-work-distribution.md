# تقسيم الخدمة ديال فريق ft_irc

## علاش درنا هاد الملف؟
هاد الملف درناه باش يكون هو المرجع ديالنا (Handbook) فهاد المشروع. الهدف منو هو ننظمو الخدمة بيناتنا باش كل واحد يعرف شنو تابعو، ونتفاداو المشاكل ديال الكود (بحال الـ Merge Conflicts). ملي كتقسم الخدمة مزيان، الفريق كيقدر يخدم فـ Parallel (كل واحد كيصاوب جيهتو فنفس الوقت)، والخدمة كتمشي بالزربة وبطريقة نقية. 

---

# أعضاء الفريق

الفريق ديالنا مكون من 3 ديال الأعضاء. كل واحد عندو مسؤولية على جزء محدد، ولكن فاللخر كاملين خاصنا نتعاونو باش نخرجو بـ Server خدام مزيان.

* **Ismail**: هو المسؤول على الهيكل العام ديال الـ Server والمنطق الداخلي ديالو.
* **Ayoub**: هو المسؤول على الشبكات (Networking) والـ Sockets والتواصل مع الـ Operating System.
* **Souhail**: هو المسؤول على الأدوات المساعدة (Utilities) وإدارة الـ Buffer والـ Parsing ديال الرسائل.

---

# القواعد العامة ديال الخدمة

باش الخدمة تمشي مزيان وما نضيعوش الوقت فحل المشاكل التقنية، غادي نلتزمو بهاد القواعد:

* **علاش خاص كل واحد يخدم غير على الجزء ديالو؟** باش نتفاداو الـ Merge Conflicts. ملي كل واحد كيخدم فملف ديالو، كيكون ساهل نجمعو الكود بلا ما نخسرو خدمة بعضياتنا.
* **علاش ما خاصش نبدلو كود ديال عضو آخر بلا اتفاق؟** حيت كل واحد فاهم المنطق ديال الكود اللي كتب. إلى بغيتي تبدل شي حاجة فكود ماشي ديالك، هضر مع مولاه وهو اللي غايبدلو ولا غيوافق ليك تبدلو.
* **علاش خاص نستعملو Git Branches؟** ممنوع نخدمو مباشرة فـ `main`. الـ Branches كيعطيوك مساحة معزولة باش تجرب وتغلط بلا ما تخسر الـ Server اللي خدام.
* **علاش Pull Requests مهمين؟** הـ Pull Request (PR) هو فرصة باش الفريق يشوف الكود ديالك (Code Review) قبل ما يدخل لـ `main`. هادشي كيخلينا نصيدو الأخطاء بكري.
* **علاش خاص نجربو الكود قبل Merge؟** أي كود غيدخل لـ `main` خاصو يكون كـ Compile وما فيهش أخطاء باينة، باش ما نوقفوش الخدمة ديال الفريق كامل.
* **علاش خاص الواجهات (Interfaces) تبقى مستقرة؟** הـ Interface (يعني أسماء الـ Functions والـ Parameters) هو العقد بيناتنا. إلى Ayoub بدل السمية ديال شي Function كيستعملها Ismail، الكود ديال Ismail غادي يحبس. داكشي علاش الـ Interfaces ما خاصهمش يتبدلو بسهولة.

# تقسيم Phase 2: Server Foundation

**الهدف ديال هاد المرحلة:** نبنيو الساس ديال الـ Server. فهاد المرحلة الـ Server غيولي قادر يشعل، يتكونفيگرا، ويحل الـ Port ويتسنى الاتصالات، وخا مازال ما غيتعاملش معاهم.

| المسؤول | المهام الأساسية | الهدف |
|---------|-----------------|-------|
| **Ismail** | Server architecture | يبني الهيكل الأساسي ديال الـ Server |
| **Ayoub** | Socket layer | يصاوب طبقة الاتصال والـ Sockets |
| **Souhail** | Utilities & Build | يقاد الـ Makefile والأدوات المساعدة |

## Ismail
**المهام:**
* **Server architecture**: كيفاش الـ Classes غادي يتواصلو بيناتهم.
* **Server class**: يصاوب الـ Class الرئيسي اللي كيتحكم فكلشي.
* **Configuration**: قراءة الـ Port والـ Password من سطر الأوامر.
* **Main lifecycle**: المنطق ديال الدوران (Loop) الرئيسي ديال الـ Server.

**علاش هاد الخدمة مهمة؟** هاد الخدمة هي الساس ديال المشروع. Ismail هو اللي غيحدد كيفاش Ayoub و Souhail غيدخلو الخدمة ديالهم وسط الـ Server.

## Ayoub
**المهام:**
* **socket()**: خلق الـ Socket الرئيسي.
* **bind()**: ربط الـ Socket بالـ Port.
* **listen()**: جعل الـ Server يتسنى الاتصالات.
* **non-blocking**: تفعيل خاصية الـ Non-blocking باش الـ Server ما يتبلوكاش فـ `recv()` أو `accept()`.
* **poll initialization**: إعداد الـ `poll()` باش يراقب الـ Sockets.

**علاش هاد الخدمة مهمة؟** هاد الطبقة هي اللي كتربط الكود ديالنا مع العالم الخارجي. بلا هاد الخدمة، الـ Server ديالنا بحال شي دار بلا بيبان.

## Souhail
**المهام:**
* **Makefile**: يقاد الـ Makefile باش يصاوب الكود كامل.
* **Helpers**: يصاوب Functions كيعاونو بحال تحويل الـ Strings.
* **Logger**: يصاوب نظام ديال التسجيل (Logs) باش نعرفو شنو طاري وسط الـ Server (مثلا: طبع رسائل Error ولا Info).
* **Build verification**: يتأكد أن الكود كـ Compile بـ C++98 وبلا Warnings.
* **Utilities**: أدوات لمعالجة الأخطاء (Error Handling).

**علاش هاد الخدمة مهمة؟** هاد الأدوات كتعاون الفريق كامل يخدم بسرعة. ملي كيكون الـ Logger خدام، كيسهال علينا نديرو Debugging.

# تقسيم Phase 3: Client Connection Management

**الهدف ديال هاد المرحلة:** الـ Server خاصو يولي يقدر يقبل الـ Clients ملي يتصلو، يقرا شنو صيفطو، ويجمع الرسائل ديالهم بشكل صحيح.

| المسؤول | المهام الأساسية | الهدف |
|---------|-----------------|-------|
| **Ismail** | Client Class & Auth | يدير التتبع ديال الـ Clients والحالة ديالهم |
| **Ayoub** | poll() Event Loop | يدير مراقبة مستمرة للـ Sockets |
| **Souhail** | Buffer Management | يقرا الرسائل ويجمعها صحيحة |

## Ismail
* **Client class**: يصاوب الكلاس اللي كيمثل كل مستخدم متصل.
* **Registration state**: يتبع واش الـ Client عطى הـ Password واختار הـ Nickname أو مازال.
* **Connection lifecycle**: يتبع وقتاش الـ Client دخل ووقتاش خرج.

## Ayoub
* **poll()**: يخدم بـ `poll()` وسط الـ Event Loop باش يراقب شكون صيفط رسالة.
* **Event Loop**: يدير الدوران المستمر اللي كيتفاعل مع المتغيرات (Events).
* **Disconnect detection**: يكتشف ملي شي Client كيقطع الاتصال.
* **File descriptors**: ينظم ويمسح الـ FDs اللي تسدو باش ما نطيحوش فـ Memory / FD Leaks.

## Souhail
* **Buffer management**: كل Client خاصو Buffer ديالو فين كيتجمعو الحروف اللي صيفط.
* **recv()**: يقرا الحروف من الـ Socket ويزيدهم فالـ Buffer.
* **Partial messages**: يتعامل مع المشكل ديال TCP ملي كيوصلو الحروف مقطعين.
* **CRLF extraction**: يقلب على `\r\n` باش يعرف بلي الرسالة كملات.
* **Preparing parser input**: يخرج الرسالة كاملة وواجدة باش Ismail يقدر يتعامل معاها ويفهم الأوامر.

# كيفاش غادي نخدمو مع بعضياتنا

* **كيفاش نخدمو بوحدنا:** كل واحد كيشد الخدمة ديالو فـ Branch مستقلة كتحمل السمية ديال المهمة. كيتعامل غير مع الملفات اللي تابعين ليه.
* **كيفاش كيتلاقاو الخدمة:** عن طريق הـ Interfaces. مثلاً Ismail غيصاوب كود كيعيط لـ `AyoubSocket.init()`، واخا Ayoub مازال ما كملش الكود من لداخل، المهم السمية ديال הـ Function كاينة ومتفقين عليها.
* **كيفاش غادي يكون Merge:** ملي واحد فينا كيسالي مهمة، كيدير Pull Request للـ `main`. الأعضاء لخرين كيشوفو الكود، وإلى كان كلشي هو هداك كيندمج (Merge) فـ `main`.
* **كيفاش نتفادو Merge Conflicts:** ما تخدمش فملف ديال عضو آخر. وإلى كان ضروري تبدل شي حاجة فملف مركزي بحال `Server.hpp`، هضر مع الفريق فـ Discord أو غيرو باش تتفاهمو شكون غيبدل فيه.
* **كيفاش نحلو المشاكل إلا وقع Conflict:** كنجلسو مجموعين فـ Call، كنشوفو הـ Conflict وكنحلوه سطر بسطر باش نتأكدو أننا ما مسحناش خدمة بعضياتنا.

# ترتيب الدمج (Integration Order)

الدمج ديال الكود غادي يمشي تدريجياً، ما غنجمعوش كلشي فدقة.

```text
       Ismail
          │
          ▼
   Server Skeleton 
     (الهيكل العام)
          │
          ├──────────────┐
          ▼              ▼
        Ayoub         Souhail
       Socket        Utilities
          │              │
          └──────┬───────┘
                 ▼
            First Merge 
          (الدمج ديال الساس)
                 │
                 ▼
           Working Server 
        (Server كيشعل و كيتسنى)
                 │
                 ▼
              Phase 3 
        (زيادة إدارة الـ Clients)
```

**شرح الخطوات:**
1. Ismail كيصاوب الساس (Skeleton) والملفات فارغة ومقادة.
2. Souhail كيدير הـ Makefile والـ Utils ويدمجهم.
3. Ayoub كيصاوب الـ Sockets ويدمجهم مع הـ Skeleton ديال Ismail.
4. كنتأكدو أن הـ Server خدام وكيحل הـ Port.
5. كندوزو لـ Phase 3 ونبداو ندخلو الـ Logic ديال הـ Clients.

# Public Interfaces (الواجهات العامة)

الـ Interface هو دوك الـ Functions اللي كيستعملهم الفريق كامل. 
* **منين كيجي Interface:** مثلاً Ayoub كيقول "هاكم הـ Function `int getNewConnection()` اللي كترجع ليكم הـ FD ديال הـ Client الجديد".
* **شكون كيستعملو:** Ismail كيستعمل هاد الـ Function وسط الـ Loop ديالو.
* **علاش ما خاصوش يتبدل بسهولة:** حيت نهار Ayoub غيقرر يبدل سمية الـ Function ويسميها `int acceptClient()`، الكود ديال Ismail غادي يخسر وما غيبقاش يـ Compile. داكشي علاش أي تغيير فالـ Interfaces خاصو تشاور مسبق.

# Git Workflow

غادي نخدمو بنظام مريح ومنظم فـ Git:

* **main**: הـ Branch الرئيسي. الكود اللي فيه خاصو ديما يكون خدام وكيـ Compile. ممنوع دير `git commit` مباشرة فيه.
* **feature branches**: أي مهمة جديدة كتحل ليها Branch خاصة بيها. كتخدم فيها وكتدير `commit`.
* **commits**: دير Commits صغار ومشروحين. مثلا "Add poll initialization" حسن من "Update files".
* **pull requests (PR)**: ملي كتسالي من الـ Branch ديالك، كتحل PR باش تدمجها مع `main`.
* **merge**: الأعضاء لخرين كيراجعو الكود، وكيقبلو الـ PR.

# Coding Rules (قواعد الكود)

باش الكود ديالنا يبان بحال إلى كاتبو واحد:

* **C++98 فقط**: ممنوع تستعمل ميزات ديال C++11 (بحال `auto`، `nullptr`، الخ).
* **ممنوع Global Variables**: كلشي خاصو يكون داخل الـ Classes باش الكود يبقى נقي.
* **ممنوع Duplicate Code**: إلى لقيتي راسك كتعاود تكتب نفس الكود جوج مرات، ديرو فـ Function وحطو فـ Utils.
* **احترام Orthodox Canonical Form**: أي Class خاص يكون فيها Default Constructor, Copy Constructor, Assignment Operator, و Destructor إلى كان ضروري.
* **أسماء واضحة**: `client_fd` حسن من `c`. `buffer_size` حسن من `s`.
* **Functions صغار**: הـ Function خاصها دير حاجة وحدة وتديرها مزيان.
* **مسؤولية وحدة لكل Class**: الـ Socket كيتكلف بالشبكة، الـ Client كيتكلف بالمستخدم، والـ Server كينسق بيناتهم.
